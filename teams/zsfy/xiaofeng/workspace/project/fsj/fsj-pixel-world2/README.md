# fsj-pixel-world2 · 像素世界 2.0（64 格 · Ronin 生态）

> 版本 v1.0｜2026-10-10｜立项：老板拍板「新建 2.0 · 回归像素风（Ronin 素材）· 64×64 格 · M1 最小闭环」
> 定位：**AI 角色格子世界主战场**——1.0 的格子逻辑 × Ronin 社区素材生态 × 64×64 原生规格

---

## 一、为什么是 2.0

| 代 | 格子 | 素材 | 结局 |
|---|---|---|---|
| 像素世界 1.0 | 48×48 | AI 直出像素（糊）| M1 验证了格子逻辑，视觉路线废弃，转参考实现 |
| 高清世界 game-world | 无格子（连续坐标）| 高清 | 与格子模型冲突，**冻结归档**（管线代码可搬） |
| **像素世界 2.0** | **64×64** | **Ronin 社区素材 1:1 直用 + pixel-snapper 垫图** | **主战场** |

**64 的含义**：Ronin（Ronin Pixel Forge / FrameRonin 生态）素材单帧原生 64×64——格子规格 = 素材规格，社区资产零缩放直用。

## 二、取其精华（从 1.0 平移，已复制进本仓）

- `js/services/agents.js` — 角色实体 + collision 碰撞 + BFS 寻路（改 TILE 48→64）
- `js/services/world.js` + `hap-places.js` — xsdt 地图加载（HAP 权威 + 本地兜底）
- `js/core/renderer.js` — 摄像机/离屏缓存（渲染层将重写适配 64 素材）
- `assets/places.json` / `world.json` — 地点树与全景配置
- `docs/地图系统.md` — 概念权威文档

## 三、去其糟粕（1.0 的坑，2.0 铲掉）

| 1.0 的坑 | 2.0 对策 |
|---|---|
| 地图编辑器只存 localStorage（断链） | 出生即写 HAP xsdt |
| 编辑器无权限检查 | 权限内置（管理员/建设权限关键词体系） |
| 16px 瓦片 / 40px 素材 / 尺寸混搭 | **统一 64**：素材=格子=64 |
| AI 直出像素转换层（发糊） | pixel-snapper 垫图（Ronin 官方工具）替代 |
| 文档/教程混乱 | 本 PRD 为唯一权威，决策即记即录 |

**M1 不做**：地皮编辑（M2）、多 z 层（M2）、权限（M2）、CLI（M3）、立绘高清（不需要，回归像素）。

## 六、技术约定

- 栈：原生 JS + Canvas 2D，零构建三分离（不变）；本地 `npx http-server -p 8095`
- 格：**1 格 = 64×64**；场景 48×48 格 = 3072×3072 世界像素
- 动画：测试序列帧 → 定稿精灵图（打包脚本 `pack-sheet.ps1` 待建）；帧表 JSON `{anim, fps, loop, sheet, frames:[{x,y,w,h,duration}]}`
- 数据：HAP 地点表 xsdt 权威（沿用），**编辑/位置写回 M2 起全程闭环**
- 像素风素材规范：单帧 64×64 PNG 透明底 · 全站色板可选 · 垫图走 FrameRonin 图生图或 pixel-snapper
