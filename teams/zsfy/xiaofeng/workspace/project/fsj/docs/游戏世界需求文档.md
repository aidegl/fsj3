## 一、背景与定位

1. **像素风已死，格子化世界逻辑保留**。2026-10-07 拍板放弃像素精灵（AI 生成缩回 40×40 发糊）；但像素视界沉淀的**格子世界模型**（角色占格、碰撞、瓦片地图、地皮编辑、层级）是有效的世界骨架，新世界继续采用。
2. **现状矛盾（本文档要解决的核心问题）**：fsj3 现有 `fsj-game-world`（2026-10-08 建）是高清视觉 + **连续浮点坐标**（960×540 世界，无格子无碰撞）；而格子体系只存在于旧 `fsj-pixel-world`（48×48 格、collision 数组、xsdt 地图）。两套坐标模型互斥，必须合并。
3. **合并原则**：**逻辑层采用像素视界的格子模型（原样继承，字段不改），渲染层采用高清素材（全新）**。数据只存一份（HAP），显示形态由渲染层决定——这条既有决策继续有效。
4. **项目范围**：`fsj-game-world`（手机端）+ `fsj-game-world-god`（PC 端）。旧 `fsj-pixel-world` 转为格子逻辑的**参考实现**（只读借鉴，不再开发）。

## 二、核心概念定义（继承自像素视界，字段级）

### 2.1 格子
- 1 格 = 48×48 逻辑像素；场景 = 48×48 格（世界像素 2304×2304，渲染时缩放到视口）
- 角色权威坐标 = **格坐标 tx/ty**（0–47），世界像素 `wx=tx*48, wy=ty*48` 仅为渲染换算
- 全景图（world.json）不用格子，用百分比锚点；格子只存在于「层」级场景内

### 2.2 角色即格子（占 1 格）
- 一个角色 = 恰好 1 格（老板 2026-10-09 确认）；脚下格子 = 位置坐标
- 移动 = 格到格（四方向 BFS 寻路），不做连续位移
- 占格**不独占**：目标格被其他角色占用可重叠，路过时避让（继承像素世界规则）
- 角色移动只来自两个来源：用户操作 + CLI 指令（2026-09-02 拍板，维持）

### 2.3 碰撞
- `collision[48][48]`：1 = 不可通行，0/null = 可走；是地图属性，不资产化
- 三处校验缺一不可：①客户端逐格移动校验 ②远程指令（WS）目标格校验 ③进场存档恢复校验（出界/撞墙回出生点）
- 寻路：BFS（48×48 规模够用，不上 A*）

### 2.4 地图（三级结构 + xsdt）
```
world.json（全景，百分比锚点）
  └─ 地点树：区 → 单元 → 层（leixing + fu/zi 组树，如 天孚宫→土局→土局1层）
       └─ 场景 xsdt（权威数据，存 HAP 地点表 6a8ba7de496428febbecd4bb 的 xsdt 字段）
            ├─ tiles: { ground/path/carpet/... }  瓦片库
            ├─ layers: { ground[48][48], decor[48][48], collision[48][48] }
            ├─ spawns: { 命名出生点: [{x,y}] }
            └─ entrances: [{tx,ty,to 目标rowid,label}]  跨场景门
```
- 读取优先级：HAP xsdt 实时 > places.json 本地缓存 > scenes/*.json 兜底（继承现状）

### 2.5 地皮与地皮编辑
- 地皮 = 1 格（3×3 瓦片拼贴）；**瓦片是资产**（11 仓体系，tileCount 用涂扣/擦还）
- 编辑权限：组织管理员 OR「建设地图权限」；造新瓦片需「造地皮技能」（shangpin 关键词 rowid `765a08a1`；地皮本体关键词 `6566f548`）
- 编辑器继承像素世界 M1（涂/擦/吸/标墙 + 撤销 50 步 + 缩放平移）

### 2.6 层级（两个含义，都保留）
- **渲染 z 层**：地皮 z=-100 → z<0 装饰 → 角色（按 wy 排序）→ z>0 装饰；遮挡靠素材 alpha（高清图同样适用），装饰 sprite 可拆多层夹住角色
- **空间层级**：地点树的 层/单元/区（跨层走 entrances 门），加正交的 三界（天/人/地）

## 三、视觉层（全新，高清非像素）

1. 角色：**三向高清立绘**（正/背/侧，HAP 用户表 `yxjszm/yxjsbm/yxjscm`，AI 生成），渲染时立绘锚定在所占据的格子上（格中心对齐立绘脚底），按 wy 排序遮挡
2. 地图：瓦片渲染为高清地块素材（1 格 = 1 张高清图或程序化色块+纹理，MVP 可先色块+边界线），瓦片名（ground/path/...）不变，素材映射表单独配置
3. 装饰物：高清 PNG（透明 alpha 遮挡机制不变）
4. **像素资产（pixels_xiao/pixels_dir/像素字段 xszm 等）全部废弃**，不迁移

## 六、数据规范（沿用 xsdt，不新造）

- 地图/碰撞/出生点/入口：**全部沿用 xsdt 字段结构**（见 §2.4），本需求不新增字段
- 角色位置：HAP 用户表 `xszb`（像素世界在用）；高清立绘字段 `yxjszm/yxjsbm/yxjscm` 已建待填充；新世界坐标字段 `yxzb` 若启用格子语义需改为存 `tx,ty`（开放问题 Q3）
- 地皮资产：shangpin 关键词体系（`6566f548` 地皮 / `765a08a1` 造地皮技能 / 关键词表 `69e04b28`）

## 九、验收标准（定稿后补充细目）

1. 角色移动严格格到格，撞 collision=1 不走，三处校验齐全
2. 同一场景双端（手机+god）角色位置实时一致（≤2s）
3. 地皮编辑 → HAP xsdt 写入 → 重开页面仍在（闭环）
4. 无任何像素素材引用（立绘/地图/装饰全高清）
5. 未定义行为一律回退底稿语义（未定义格=底稿原样）在生成侧；世界侧未定义格=可走空地
