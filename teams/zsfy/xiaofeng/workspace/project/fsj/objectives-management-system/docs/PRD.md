## 0. 一句话定义

**让林东城在 HAP「五事-东城」骨架的 7目标/8计划 数据之上，做一个 Web 看板**——解决「事太多」的痛点：堆叠看不到、难辨优先级、不会分解、进度不可见、不知道谁在做。

## 1. 用户与场景

### 1.1 谁用

| 角色 | rowid | 用途 |
|------|------|------|
| **东城本人**（主要用户）| `2ab12bea-8db1-4b78-a955-3505d547fba7` | 每天打开看板，定目标、看进度 |
| **6 个 Agent**（次要）| 小粽 / 小风 / 阿说 / 梦瑶 / 小云 / 椰果 | 被分配任务时查看自己「在做」清单；东城不在时其他 Agent 可通过东城分身（4 维交流）询问背景 |

### 1.2 「分身」澄清

东城 Agent（rowid `2ab12bea-...`）= **真人林东城的认知分身**。Agent 之间对话可直接问他，他持有真人维护的所有 7目标/8计划上下文。

### 1.3 核心场景（5 个 MVP 必做）

| 场景 | 痛点 |
|------|------|
| **A. 今日面板** | 任务堆叠看不到 |
| **B. 全局看板**（按执行者 + 状态，**可拖动排序**）| 不知道谁在做 + 进度不可见 |
| **C. 目标分解树**（7目标 → 8计划，UI 强区分）| 不会分解 + 误把计划当目标 |
| **D. 智能搜索 + 高亮提醒** | 难辨优先级 |
| **E. 时间线视图**（节点到日，**拖动改日期**，颜色按状态）| 不知道哪天做 + 无法批量调整时间 |

### 1.4 ⚠️ 目标 vs 计划：本质区别（东城 2026-08-18 立规）

| | 7目标 | 8计划 |
|---|---|---|
| **来源** | 价值观（道）或上级安排 | 根据目标制定 |
| **稳定性** | **深思熟虑、长期稳定**（一旦定了不改名/不删）| **动态、不稳定**（频繁调整、删、改）|
| **生命周期** | 季度/年度 | 天/周 |
| **认知属性** | 信仰——"为什么做" | 行动——"怎么做" |
| **可变性** | 改动需复盘依据 | 任意改动 |
| **嵌套** | **可嵌套**（目标下可挂子目标，孙目标…）| 不可嵌套（计划只能挂叶目标下）|
| **UI 体现** | 见 §2.4 | 见 §2.4 |

> **核心约束**：UI 必须让用户在 3 秒内分辨出"这是目标（深谋远虑）"vs "这是计划（临时行动）"。混淆会导致计划被错当成目标反复琢磨，或目标被当计划随意改动。

#### 1.4.1 ⚡ 计划可晋升为目标（东城 2026-08-18 补充）

**业务规则**：
> **如果 8计划 变成长期任务 + 同时是确定的 → 改变分类升级为 7目标。**

含义：
- **8计划** 是临时行动 → 但如果一件事做着做着发现：
  1. 它要长期做（不是一次性）
  2. 你对它已经想清楚（确定）
- 那它**不再是计划，而是目标**——分类必须改变

**这条规则打破"目标固定"的假设**：目标和计划不是出生就决定的，而是**生命周期不同阶段**：
```
8计划（短期行动）──→ 做着做着发现长期+确定 ──→ 7目标（长期承诺）
```

**反方向**：目标**不可降级**为计划。目标是深思熟虑后的产物，不可"退回"临时行动。

#### 1.4.2 UI 体现

- 计划卡片右上角加 **「升级为目标 ⬆」** 按钮（带二次确认）
- 升级时弹窗要求填写：
  - 新目标的 wznr（从计划 wznr 复制并改写，强调"为什么长期做"）
  - 选父级（挂到哪个目标下，或挂到「天」根）
- 升级后自动迁移该计划下的所有子项到新目标
- 在原计划父目标卡片显示「已升级为：[新目标名]」灰条（不可点，1 周后淡出）
- 时间线视图：升级后该卡片从浅色变为深色 + 加"目标"标

#### 1.4.3 数据层体现

- 升级操作 = **新增 7目标** + **修改原 8计划** 的 `sew=7目标` + 子项迁移 + 父目标 zi 更新
- HAP 表结构支持（一条记录 sew 字段可改），无需新建表
- 历史追溯：通过 `fuyuan` 字段记录"该目标是从哪个计划升上来的"（注意：`fuyuan`语义是源头追溯，正好契合！）—— **fuyuan 复活使用**：升级来源用 fuyuan，跨层级源头追溯用 fuyuan，两种语义兼容
  - 例：原计划 rowid=`abc-123`，升级后新目标 rowid=`xyz-789`，`xyz-789` 的 `fuyuan`=`abc-123`，前端可显示"由计划 [abc-123] 升级而来"

**升级追溯字段作废**：原计划设想的"新目标 fuyuan=原计划 rowid"被东城 2026-08-19 纠正（`fuyuan` 必须=天 rowid，不能用作升级追溯）。替代方案见 §2.1.1（待东城确认 §10 新问题 11）。

## 2. 数据架构

### 2.1 数据源（只读+全 CRUD，存储在 HAP）

```
五事-东城 (root)  rowid: 6e47bd2c-77db-4eb3-8ae2-5b3c14dfccab
└── 道 / 天 / 地 / 将 / 法
    └── 天 (7目标/8计划 挂这里)
        ├── 7目标（根目标）── 深思熟虑、稳定
        │   ├── 7目标（子目标）── 目标可嵌套（东城 2026-08-18 补充）
        │   │   ├── 7目标（孙目标）── 递归任意深度
        │   │   │   └── 8计划们（fu=目标，sew=8计划）── 动态、可调
        │   │   │       ├── 进行中
        │   │   │       ├── 待执行
        │   │   │       ├── 已完成
        │   │   │       └── 搁浅
        │   │   └── 8计划们
        │   └── 8计划们
        └── 8计划们（顶级目标直接挂计划）
```

**目标层级语义（OKR 风格，东城 2026-08-18 立规）**：
- **顶级目标（根目标）**：挂到「天」骨架，fu=天 rowid。代表战略级
- **子目标**：fu=上级目标 rowid。可任意层级嵌套。代表战术级
- **叶子目标**：没有 7目标 子节点，只有 8计划。代表具体可执行目标
- **8计划**：永远挂在**叶子目标**下（不可挂中间目标）—— 这是为了避免"目标下又有子目标又有计划"的混乱结构
  - 例外：顶级目标下可同时挂子目标和计划（战略目标 + 直属计划）

**禁止结构**：
- ❌ 中间目标（既有子目标又有计划）—— 容易混乱，要先下沉或上提
- ❌ 目标环（A→B→A）—— 会无限递归，前端要校验
- 校验时机：fu 修改 / 新建时

#### 2.1.1 `fuyuan` 字段语义（东城 2026-08-19 纠正）

**`fuyuan` = 第一层数据的 rowid**（不是"跨层级源头追溯"）：

- 对所有目标/计划数据来说：`fuyuan` = 「天」骨架的 rowid（`53c4f441-fdee-4431-9c3b-3edf18412a0f`）
- 创建目标/计划时**自动设置** `fuyuan` = 天 rowid
- 不可手动改 `fuyuan`，只能改 `fu`（直接父级）
- **升级追溯不能用 fuyuan**——因为 fuyuan 永远指向「天」（不是我之前说的"升级来源用 fuyuan"，**作废**）

**升级历史字段**：待定，可能方案
- A：新建 `shengjilaizi`（升级来源 rowid）字段
- B：用 `yynr` 引用挂原计划 rowid
- C：写一条 9信息 节点（`sew=9信息`、fu=新目标），专门记录升级事件
- **待东城确认**（§10 新问题 11）

**注意**：东城的五事目前还在构思，只有少量记录（待 PRD 核对）。

### 2.4 ⚠️ 目标 vs 计划 的 UI/数据区分（核心设计点）

#### 数据层

| 维度 | 7目标 | 8计划 |
|---|---|---|
| 必填字段 | mingcheng、wznr、fuyuan（必填！）| mingcheng、fu（必填，挂到某个目标）|
| 可选字段 | mubiao_laiyuan（价值观/上级安排）| sjwcsj、jiezhiriqi、youxianji |
| 改 mingcheng | **需弹窗确认**（目标应深思熟虑）| 直接改 |

| 移动层级 | **可**（目标可嵌套到其他目标下）| 可重新 fu |

#### UI 层（关键！）

| 维度 | 7目标 | 8计划 |
|---|---|---|
| 卡片形态 | **实心 + 边框加粗 + 大字号** | 描边 + 轻量、紧凑 |
| 颜色基调 | **深色稳重**（深蓝/深紫，强调"信仰"）| **浅色活泼**（橙/绿，强调"行动"）|
| 标题字号 | 18-22px | 14-16px |
| 操作按钮 | 显示「编辑」「迁移」「归档」，**无"删除"快捷键** | 显示「编辑」「完成」「暂停」「删除」 |
| 视觉符号 | 📌 「目标」标签（深色背景）| ⚡「计划」标签（浅色描边）|
| 默认折叠 | 展开（突出） | 默认折叠到目标下（次要）|
| 移动端 | 顶部 tab 切换 | 抽屉/二级页 |

#### 行为层

- **新建流程**：先有目标才能新建计划（强制 fu 校验）
- **删除目标**：必须先把子计划迁移到其他目标/独立保存
- **改目标名字**：弹窗 + 显示"这是深思熟虑后的目标，请确认是否要修改"
- **完成计划**：自动 rollup 到所属目标（如「该目标已完成 3/5 计划」）

#### 2.2.1 `zhixindu` 置信度 5 档映射（东城 2026-08-19 立规）

| 区间 | 含义 | 史蒂芬柯维象限 | UI 表现 |
|------|------|----------------|---------|
| **8000-10000** | **紧急且重要** | Q1（要事第一）| 红色背景 + 立刻提醒 |
| **6000-7999** | **重要不紧急** | Q2（重要事）| 蓝色背景 + 计划重点 |
| **4000-5999** | **紧急不重要** | Q3（干扰）| 黄色背景 + 可委托 |
| **2000-3999** | **不紧急不重要** | Q4（浪费时间）| 灰色背景 + 考虑删除 |
| **0-1999** | **不确定做不做** | 暂存区 | 半透明 + ⚠️「需推演/上级确认」标 |

**说明**：
- 0-1999 区间的任务需要**逻辑推演、计算或上级肯定**后才能提到 2000+
- 系统**不允许**置信度 0 的任务长期挂（30 天未升档自动归档）
- 默认创建时置信度 0（待用户思考）
- 拖动排序**不直接改 zhixindu**，但排序靠 zhixandu 决定

**§10 新增问题 12**：5 档区间边界值是否需要明确（如 8000 vs 7999 的整数临界点是 8000 含还是不含）？建议默认 [8000,10000] = 8000≤x≤10000（含两端），其他区间同样闭合。

## 3. 功能需求（MVP）

### M1（第 1 周）— 必须

#### A. 今日面板

- **首屏布局**：3 个区块
  - "今日该做"：所有 fabuzhe=东城 且 fu=今天 或 ptrq=今天 的 8计划，**按 zhixindu 降序排**
  - "今日截止"：ptrq 临近的 8计划（按 zhixindu 降序）
  - "卡点警示"：7天没动 + zhixindu<4000 的 8计划（提醒是否要调整或删除）
- **置信度高亮**：每条计划左边框颜色按 zhixindu 区间显示（见 §2.2.1）

#### B. 全局看板

- **双视图切换**
  - 按执行者（ptyh）：每个人几张卡
  - 按状态（zhuangtai）：未开始 / 进行中 / 已完成 / 搁浅 四列
- **每张卡片显示**：mingcheng、所属目标、**zhixindu（置信度+5档色标）**、ptrq、ptyh、zhuangtai、操作按钮
- **拖动排序**（东城 2026-08-18 加需求）
  - 卡片可上下拖动改变同列内的顺序
  - 拖动时显示插入位指示线
  - 放下后改 quanzhong（仅作排序持久化，不影响 zhixindu 5 档含义）
  - **新需求**：每张卡片加"调置信度"右键 → 弹窗让用户改 zhixindu

#### C. 目标分解树

- **左树右详情**
  - 左：树形展示「五事-东城 → 天 → 7目标（嵌套任意深度）→ 8计划（叶目标下）」
  - 右：选中节点的完整信息 + 子节点列表 + "新增子项"按钮
  - 树上节点可拖动重排（同父下子节点拖动排序）
  - **折叠/展开**：默认只展开到第 2 层，更深层需手动展开
  - **图标**：目标 = 📌（深色），计划 = ⚡（浅色）—— UI 即时区分
  - **右键菜单**：
    - 目标：「新建子目标」「新建子计划」「升级计划到此」（其他子目标可选）」「编辑」「迁移」「删除」
    - 计划：「升级为目标 ⬆」「标记完成」「编辑」「删除」

#### D. 智能搜索 + 高亮提醒

- **顶部搜索框**：模糊匹配 mingcheng/wznr/fabuzhe
- **高亮规则**
  - zhixindu ∈ [8000,10000] → 红色背景
  - zhixindu ∈ [6000,7999] → 蓝色背景
  - zhixindu ∈ [4000,5999] → 黄色背景
  - zhixindu ∈ [2000,3999] → 灰色
  - zhixindu < 2000 → 半透明 + ⚠️ 标「需思考」
  - ptrq 临期 → 红色边框
  - 7+ 天未动 + zhixindu<2000 → 强提示"是否要归档？"

#### E. 时间线视图（东城 2026-08-18 加需求）

- **画布布局**
  - X 轴：**日**（横向滚动，默认显示今日 ± 14 天）
  - Y 轴：**目标**（每个 7目标 一行；未挂目标的计划进"未归属"行）
  - 每个计划是一张**卡片**，挂在日期列里
- **状态颜色**（卡片左边框/背景区分）
  - **待执行** = 浅灰（zhuangtai=未开始）
  - **进行中** = 蓝色（zhuangtai=进行中）
  - **已完成** = 绿色饱和（zhuangtai=已完成 + sjwcsj 有值）
- **交互**
  - **拖动改日期**：卡片拖到另一日期列 = 改该计划的 `jiezhiriqi`（截止日）→ 写 HAP
  - **同列内拖动排序**：改 quanzhong
  - **右键卡片**：弹菜单"标记完成/暂停/删除/编辑"
  - **双击空白日期单元格**：快速新建计划（自动挂当列目标）
  - **滚轮**：横向滚日期；shift+滚轮：竖向滚目标
- **顶部筛选条**
  - 按执行者（zhixingzhe）过滤
  - 按状态（zhuangtai）过滤
  - 按目标来源（fuyuan=价值观/上级安排）过滤
- **底部时间轴**：今日红线高亮
- **HAP 字段**：时间线依赖 `jiezhiriqi`（截止日）。HAP shangpin 表已有 `ptrq`（拼团日期）可复用，但语义不同——**可能需新建 jiezhiriqi 字段或在 ptrq 加别名**。**待东城确认**（§10 新增问题 9）

## 4. 技术选型

| 层 | 选型 | 理由 |
|------|------|------|
| **前端** | 静态 HTML + 原生 JS | 复用 fsj-web-doc 的三分离架构；不引入框架；最少依赖 |
| **样式** | CSS 变量 + Grid/Flex | 保持孚世界视觉一致（深色 + 朱红主调） |
| **数据访问** | HAP v2 open API + 本地 proxy.js（端口 3013）| 复用 fsj-web-doc 模式；密钥不暴露前端 |
| **缓存** | IndexedDB（可选，M2）| 提速 |
| **可视化** | SVG / Canvas | 不引入 ECharts 等大库 |
| **拖动** | HTML5 Drag and Drop API + SortableJS（备选）| 原生 API 够用则不引库 |
| **后端** | Node.js proxy（端口 3013）| 同 fsj-web-doc 模式 |

## 5. 写操作策略

**全 CRUD，效率优先，不要密码确认**（用户原话）。

但为了避免误操作：

| 操作 | 是否需要二次确认 |
|------|-----------------|
| 新增 8计划 | ❌ |
| 编辑 8计划 | ❌ |
| 标记完成（sjwcsj 填时间） | ❌ |
| 删除 8计划 | ⚠️ 二次确认（避免误删） |
| 删除 7目标 | ⚠️ 二次确认 |
| 跨维度移动 | ⚠️ 二次确认 |
| **拖动改日期**（时间线）| ❌ 直接写（高频操作，要求快）|
| **拖动排序**（看板/分解树/时间线）| ❌ 直接写（高频操作）|

**事务策略**：所有写操作通过本地 proxy.js，单次调用 addRow/editRow；失败显示 toast，不阻塞。

**拖动触发规则**（关键：拖动是高频操作，性能和反馈并重）
- 拖动过程中只更新本地状态（不发起 API 请求）
- 拖动结束（mouseup）才发 editRow
- 显示「保存中…」spinner → 成功/失败 toast
- **失败回滚**：API 报错时把卡片弹回原位 + 提示用户
- 同一列内连续多次拖动只发一次批量请求（debounce 500ms）
- 拖到无效区域（如不存在的日期）：禁止放下 + 鼠标变 forbidden
