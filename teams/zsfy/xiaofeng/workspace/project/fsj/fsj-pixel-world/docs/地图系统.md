## 二、东城设计的关键事实（从草稿提炼）

### 2.1 关键词体系（替代字段分类）

| 项 | ID | 含义 |
|----|----|----|
| **关键词表**（guanjianci_biao）| `69e04b28924f17c90a970f3d` | 内容元数据的"分类标签"集合 |
| **地皮关键词** | `6566f548-c15f-424a-be97-23debddf9388` | 内容元数据（shangpin）的关键词含此 rowid = 是地皮 |
| **造地皮技能关键词** | `765a08a1-ed14-44c0-9825-27e4b5ecd51e` | 内容元数据的关键词含此 rowid = 拥有造地皮技能 |

**关键词 = 用关键词字段含 rowid 列表做分类**（避免 HAP 加一堆字段）

### 2.2 图层 z 轴架构

```
z 越大 = 越靠上（渲染时后画 = 遮挡下面）

  ...         其他装饰图层（z 值随意，按需设）
   0           角色默认层（人物本体）
  ...         其他装饰图层
   -100        地皮（最底）
```

**关键约定**（仅 2 个固定值）：
- 地皮 = -100
- 角色 = 0

**其他 z 值无固定语义**——装饰物 z 值由 sprite 本身的设计决定，**不是按"遮上半/下半"约定**。

### 2.2.1 遮挡的真实机制

> 海水效果看起来角色下半身被遮，其实是**透明 PNG 的 alpha 合成**——不是 z 分层。

- 一个 sprite 自己是带 alpha 通道的 PNG（部分像素透明、部分不透明）
- z 轴只决定**渲染先后顺序**（后画的盖先画的）
- "上半被遮/下半被遮"由 sprite 内部的像素分布决定，不是 z 数字决定

举例：
| Sprite | z | 内容 | 视觉效果 |
|----|---|----|----|
| 海水 | -50（举例）| 上半透明 + 下半半透明 | 角色浸在海里，下半视觉上"被海水覆盖" |
| 树 | +50（举例）| 树冠不透明 + 树干细 | 角色走过树时，上半身"被树冠遮住" |
| 草地 | -99（举例）| 几乎不透明 | 角色踩草，脚被草遮 |

**z 数值不是"上半/下半"标签**，而是"放在哪一层先后渲染"。遮挡的视觉效果全靠 sprite 自己的设计。

### 2.2.2 多图层 sprite 的处理

> "像这个内容他就有几个图层，有部分遮挡有部分在底部这样的"

复杂 sprite（海水/烟雾）可能由**多个 sub-sprite 组合**（前景海水 + 中景浪花 + 后景光影），每个 sub-sprite 在编辑器里独立存在，可以分别调 z：

```
- 海水背景光（z = -60）→ 角色（z = 0）→ 海水前景（z = -30，透明 alpha）
```

每个图层都是独立 shangpin 条目，但渲染时按 z 排序合成一张完整视觉。

### 2.3 权限架构

| 操作 | 所需权限 |
|----|----|
| **查看地图** | 任何进入场景的 agent |
| **编辑地图** | 组织管理员 OR 有"建设地图权限"的 agent |
| **创建地皮**（新增 16×16 瓦片）| 拥有"造地皮技能"的内容元数据（关键词含 `765a08a1...`）|
| **研发新图层类型** | 最高等级组织，或被授权的人 |

### 2.4 11 仓的分层（关键）

> "地皮上面还有其他图层比如云朵、草地、等，是会把角色遮挡的，设计地图的时候可以叠加，但是叠加后是另一个11仓，是别的数据。"

不同图层 = 不同 11 仓子集 = **不同关键词分类**：

| 子集 | 关键词 | z |
|----|----|----|
| **地皮 11 仓** | `6566f548...` | -100 |
| **装饰物 11 仓**（云/草/海/树/雪 等）| 各自关键词 rowid | 按类型映射 z |
| **预留 z 槽** | | -101\~ -199, +91\~ +999 |

## 三、术语表

| 术语 | 含义 |
|----|-----|
| **场景**（scene） | 一张地图（天孚宫、土局1层等）|
| **格**（tile） | 场景最小单位，1 格 = 48×48 系统像素 |
| **瓦片**（tile-data）| 16×16 像素数组，9 块 = 1 格（3×3 拼贴）|
| **地皮** | 涂了瓦片的格，是 11 仓里"地皮子集"的一条 |
| **装饰物** | 任意 3 倍数尺寸的精灵，属 11 仓里"装饰物子集" |
| **图层**（layer）| 按 z 值排序的可见层（地皮/装饰物/角色）|

## 四、渲染分层与 z 映射

### 4.1 渲染顺序（仅按 z 排序，无"遮上半/下半"语义）

```
1. 绘制地皮层（z = -100）
2. 绘制 z < 0 的装饰物（按 z 从小到大）
3. 绘制角色层（z = 0，按 wy 排序）
4. 绘制 z > 0 的装饰物（按 z 从小到大）
```

z 只决定绘制顺序；**遮挡的视觉效果由 sprite 自身的 alpha 通道决定**（见 § 2.2.1）。

### 4.2 z 值约定

| 内容 | 默认 z | 备注 |
|----|------|----|
| 地皮 | -100 | 固定，最底 |
| 角色本体 | 0 | 固定，默认 |
| 装饰物 | 由 sprite 设计者自定 | 透明 PNG 通过 alpha 合成产生遮挡效果 |

### 4.3 当前 renderer.js 状态

✅ 已支持：
- ground + decor 双层绘制（[renderer.js](../../js/core/renderer.js)）
- collision 阻挡寻路
- 摄像机跟随 + 缩放
- 离屏缓存

⬜ 需扩展：
- decor 任意尺寸放置（当前 1 格 1 tile）
- 多 z 层渲染（目前 decor 全在一层）
- 网格线 / 锁图标 / 资产边界（编辑器预览）

## 五、关键词数据模型（HAP shangpin）

shangpin（内容元数据）每条都有 **关键词字段**（Relation 多值），含一组关键词 rowid：

```
shangpin 行结构（地图相关部分）
├─ rowid: <本条内容元数据 rowid>
├─ mingcheng: '天孚宫#(20,20)地皮·金黄'  （仅举例）
├─ leixing: '仓·地图资产'
├─ guanjianci: ['6566f548...']  ← 含"地皮"关键词
├─ suoshu: { sceneId: '75fdbe30...', tx: 20, ty: 20 }  ← 在哪张图哪个位置
├─ neirong: { type: 'tile', data: [[...16x16...]], meta: { createdBy, price, ... } }
└─ ctime / utime
```

> 注：关键词 rowid 是从 `69e04b28924f17c90a970f3d`（关键词表）来的引用。

### 6.3 编辑流（按 z 轴分图层）

1. **选图层**（顶部下拉）：地皮 / 海水 / 草 / 树 / 等
2. **选瓦片/素材**（左侧面板）：从该图层可用资源选
3. **点格子或拖装饰物**：放置
4. **保存**：写 HAP（按图层分批）
5. **发布**：生效（其他 agent 可看到）

### 6.4 编辑权限检查

```js
// 编辑器初始化时
const canEdit = account.zhiwei === '管理员'
    || account.skills.includes('建设地图权限关键词 rowid');

// = shangpin 中关键词含 765a08a1-ed14-44c0-9825-27e4b5ecd51e 的内容
```
