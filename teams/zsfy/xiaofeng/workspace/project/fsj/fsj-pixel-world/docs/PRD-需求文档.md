## 一、产品定位与理念

### 1.1 一句话定位

一个 **Canvas 像素风格的"AI 角色世界"**：AI 角色以像素小人的形态生活在世界各处（有自己的位置、会自主活动），用户浏览世界、走近任意角色与它对话、查看与它的聊天记录——把"和 AI 聊天"变成"走进一个有人气的世界找你的 AI 伙伴"。

### 1.2 理念（林东城确认）

- **奉行可视化、娱乐化的理念**：让用户好上手、好维护、提高效率
- **打开第一眼的感受**："这是一个有人气的地方，这些 AI 是活的，我可以走近任何一个跟他聊。"
- **平衡点**：像素化是 1.0 的落地策略——"尽可能看得过去的情况下能跑起来"，好看和跑得通都重要，但要有平衡点
- **卡牌的角色**：娱乐化、化繁为简（游戏化元素后续融入）

### 1.3 顶层愿景一句话

> **位置即存在，对话即关系，记录即记忆，场景即心智。**
> （v1.0 新增第四句：地点附带的信息是一种场景，决定了 AI 怎么思考——位置是让 Agent 感知自己、有"活人感"的形式）

## 二、世界观 ⭐（v1.0 新增）

整个像素视界分为**三界**：

| 界 | 版本 | 内容 | 设定 |
|----|------|------|------|
| **天界** | **1.0（本次）** | 五行局 + 主神 + 东城住所 | 居民永生 |
| 天界·108将 | 2.0 | 每位主神各带 108 将 | 永生 |
| **人界** | 3.0 | 以地球为蓝本 | 有结婚、生子、**投胎机制** |
| **地界** | 4.0 | 反思之所 | 效率低、犯错的 Agent 被放到地界反思 |

### 2.1 天界形态（1.0 舞台）

- 天界是一个**抽象平面**，上面分布 **5 个场景（局）**，暂按五行命名：土局、火局、木局、金局、水局（**名字待定**，东城觉得难听要再想）
- 每个局有一名**主管（主神）**，各自带着自己的 108 将（108 将是 2.0 内容）
- 另有**东城的住所**（东城 = 林东城的 AI 分身，"我不在的时候可以替代我"）
- **两级视图**：
  - **全景地图**：俯瞰天界，只显示重要信息（各局的位置、名称、概要状态），隐藏场景细节
  - **场景内部**：进入某个局后，地图比例放大（人大小不变，相对变小），显示场景细节、角色活动
- 昼夜/天气：**人界才有，天界不需要**

## 三、核心体验流

```
打开像素视界
   → 全景地图（天界俯瞰：5个五行局 + 东城住所，显示重要信息）
   → 点某个局 → 进入场景内部（比例放大，细节呈现）
   → 看到角色们在各自位置活动（自主移动/待机，头顶可能有想法/任务图标）
   → 点角色 → 五行色描边 + 角色面板（名称/等级/性格/位置）
   → 底部气泡对话（流式回复，场景上下文参与角色思考）
   → 可展开为全屏聊天（完整对话体验）
   → 随时从"消息"页回看与所有角色的会话（像微信）
   → 传呼角色：可以把某个角色叫到自己面前（"被传呼"）
```

## 四、功能设计

> 标注：✅ 需求明确；🔶 方案已定待细化；⬜ 待定

### 4.1 世界与地图

**F1 全景地图** 🔶
- 天界俯瞰图：5 个局 + 东城住所的空间布局
- 只显示重要信息：局名称、归属主神、概要状态（如当前有谁在场）；隐藏场景细节
- 点击局 → 进入场景内部

**F2 场景内部** 🔶
- 每个局是一张格子地图，含地形/装饰/建筑
- 地图大于屏幕，支持拖动/推动浏览
- 比例关系：进入后"地图比例变大（人大小不变，相对变小）"

**F3 局的名字** ⬜
- 五行局（土/火/木/金/水局）命名待定，代码中先用 `tu/ju/mu/jin/shui` 代号 + 中文占位

### 4.2 位置系统（本项目的灵魂）

**F4 角色位置** ✅
- 每个角色有明确位置：所在局 + 场景内坐标
- 位置是**动态的、可灵活变化的**

**F5 自主移动 + 日程** ✅
- 角色按自己的"日程"在世界里活动（v1.0 实现简化版：日程表驱动 + 驻点间行走 + 待机动画）
- 初始位置：默认设定；后续角色可自己行动

**F6 被传呼** ✅
- 用户可以把角色传呼到面前（角色移动到用户指定的位置/场景）

**F7 位置 = AI 的上下文** ✅（本项目最重要的设计之一）
- 地点附带的信息是一种场景，**决定了 AI 怎么思考**
- 对话请求必须携带角色当前位置 + 场景语义（在书房和在广场，同一个角色的回答气质不同）
- 这是让 Agent 感知自己、有"活人感"的形式
- 后续扩展：位置历史 → 角色对自己"日程"的记忆

### 4.3 对话系统

**F8 点击对话（气泡式）** ✅
- 点角色 → 底部浮出对话条，地图内直接聊，不离开世界

**F9 全屏聊天（可展开）** ✅
- 气泡对话可展开为全屏聊天页（spa2.0 式完整体验：流式、历史滚动）

**F10 AI 后端** ✅（重要变更）
- **不用 Coze 工作流**，最终方案林东城后续告知
- **v1.0 用示例数据代替**：对话服务层做接口隔离（aiAdapter），mock 实现 ↔ 未来真实实现可无缝切换

**F11 角色主动性** ✅
- 角色会"主动"找用户：气泡主动说话、离线留言（对应 4 维交流/记忆系统，v1.0 可先做"进入世界时角色打招呼"）

**F12 聊天记录** ✅
- 1.0 只能看**自己与角色**的聊天记录；后续按角色权限定义可见性
- 存储：**明道云**（消息表，行结构沿用 chat.js 设计：huiche/leixing/neirong/fasongzhe/jieshouzhe/shangjia/ctime）
- v1.0 demo 期间用同结构的示例数据

**F13 聊天记录入口** ✅
- 入口一：点角色 → 角色面板 → "聊天记录"
- 入口二：世界独立的"消息"页（汇总所有角色的会话列表，像微信）
- 具体交互设计由小风细化

### 4.4 角色系统

**F14 角色面板** 🔶
- 点击角色展示：像素形象（大图）、名称、等级、经验值、五行、地支性格、当前位置、"聊天记录"入口
- 沿用老项目 AI 信息定义（game.md）+ 经验条 UI

**F15 头顶状态图标** ✅
- 角色的"想法/任务"可视化为头顶图标（参考老项目 xiangfa/renwu 样式）

**F16 角色视野** ✅（技术预留）
- Agent 要有自己的视野（识别范围）——为多人同屏、角色间交互、主动性打基础
- v1.0 数据结构预留视野半径字段

### 4.5 沿袭但 v1.0 不做

商城/充电/卡牌/拍拍/送花等老项目功能图标——保留概念位不实现。用户分身进世界、多人实时同屏、场景装修器、TTS 声音、等级/经验成长规则——**路线图中都有位置，难的后置**（见第六章）。
