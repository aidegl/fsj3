# 内容发布与审核流程

> 版本：v1.0
> 创建时间：2026-07-11
> 适用范围：fsj 平台所有内容（文章/想法/任务/知识等）

---

## 一、设计背景

### 1.1 问题

之前发布内容时，前端直接调用 `Fsj12wei.createBlocks` 将 JSON 拆成多层子记录。存在以下问题：
- 发布慢：N 条子记录串行创建，每条需 0.6-1.5 秒
- 未审核内容已入 12维系统，污染数据
- 内容编辑需要复杂的多版本管理

### 1.2 解决思路

**两阶段设计**：发布时只存 JSON，审核后拆子记录

```
用户发布 ─→ 存 JSON 到父记录 wznr ─→ 审核机制 ─→ 拆成 12维子记录
```

**好处：**
- ✅ 发布瞬间完成（只建一条记录）
- ✅ 前端 UI 快速渲染（直接读 wznr JSON）
- ✅ 未审核数据不污染 12维结构
- ✅ 审核机制（人/AI/算法）后期随意替换
- ✅ 支持内容编辑的二次审核

## 二、核心字段

### 2.1 审核相关字段（内容元数据表 shangpin）

| 字段 | 类型 | 说明 |
|------|------|------|
| `shenhe` | 选项字段 | 审核状态：`"待审核"` / `"二次审核"` / `"已审核"` |
| `wznr` | 文本 | **当前生效**的 JSON 正文（审核后版本） |
| `shnr` | 文本 | **待审核**的 JSON 正文（编辑后暂存） |

### 2.2 shenhe 状态枚举

| 值 | 含义 | 列表可见 | 显示内容 |
|----|------|---------|---------|
| `"待审核"` | 首次发布，等待审核 | ❌ 不可见 | — |
| `"二次审核"` | 已审核过的内容被编辑，新内容待审核 | ✅ 可见 | 显示 **旧内容**（wznr） |
| `"已审核"` | 审核通过 | ✅ 可见 | 显示 **当前内容**（wznr） |

### 2.3 字段关系图

```
┌──────────────────────────────────────────────┐
│  父记录（shangpin 表）                        │
│                                              │
│  mingcheng: 标题                              │
│  mdnr:      摘要                              │
│  zhutu:     封面                              │
│  fabuzhe:   发布者 rowid                      │
│  shenhe:    "待审核" / "二次审核" / "已审核"    │
│                                              │
│  wznr:  当前生效 JSON  ◀── 详情页读这里        │
│  shnr:  待审核 JSON（仅 shenhe="二次审核" 时）│
└──────────────────────────────────────────────┘
           │
           │ 审核通过后拆分
           ▼
┌──────────────────────────────────────────────┐
│  子记录群（12维层级结构）                      │
│                                              │
│  根节点（sew=2想法）── fu 指向父记录            │
│    ├─ 子节点（sew=3项目）                      │
│    │    ├─ 孙节点（sew=7目标）                  │
│    │    └─ 孙节点（sew=11仓）                   │
│    └─ 子节点（sew=2想法，文本块）               │
│                                              │
│  所有子记录通过 fu 字段指向父记录               │
│  父记录通过 zi 字段记录所有子记录 rowid          │
└──────────────────────────────────────────────┘
```

## 三、发布流程

### 3.1 前端发布（publish.js）

**前置条件：登录检查**

用户点击发布按钮时，首先检查登录状态（`localStorage.getItem('fsj_openid')`）。如果未登录：
- 弹窗提示「请先登录后再发布」
- 自动跳转到「我的」页面引导登录
- 不执行后续发布逻辑

**发布流程：**

登录通过后，用户填写标题、摘要、封面、正文（blocks JSON）后点击发布：

```javascript
// 1. parseContent 输出 JSON
var contentObj = parseContent(publishToolbar.editable);
// contentObj = {
//   mingcheng: "标题",
//   mdnr: "摘要",
//   sew: "2想法",
//   blocks: [
//     { type: "text", content: "正文段落" },
//     { type: "sew-node", sew: "3项目", mingcheng: "某项目",
//       children: [...] }
//   ]
// }

// 2. 直接创建一条父记录，wznr 存 JSON
callMingdaoAPI('https://api.mingdao.com/v2/open/worksheet/addRow', {
  worksheetId: 'shangpin',
  triggerWorkflow: true,
  getSystemControl: 'false',
  controls: [
    { controlId: 'mingcheng', value: contentObj.mingcheng },
    { controlId: 'mdnr',      value: contentObj.mdnr },
    { controlId: 'leixing',   value: '文章' },
    { controlId: 'sew',       value: contentObj.sew, valueType: 2 },
    { controlId: 'wznr',      value: JSON.stringify(contentObj) },
    { controlId: 'zhutu',     value: coverUrls.join(',') },
    { controlId: 'fabuzhe',   value: userRowid, valueType: 2 },
    { controlId: 'shangjia1', value: '1', valueType: 2 },
    { controlId: 'shenhe',    value: '待审核' }  // ⭐ 待审核
  ]
});

// ❌ 不再调用 Fsj12wei.createBlocks
```

### 3.2 发布后的数据结构

**父记录（唯一一条）：**

| 字段 | 值 |
|------|-----|
| mingcheng | 文章标题 |
| mdnr | 文章摘要 |
| leixing | 文章 |
| sew | 2想法 |
| wznr | `{"mingcheng":"标题","mdnr":"摘要","sew":"2想法","blocks":[...]}` |
| shnr | (空) |
| shenhe | `"待审核"` |
| zhutu | 封面 URL |
| fabuzhe | 发布者 rowid |

**子记录**：无（等待审核后创建）

## 四、审核流程

### 4.1 首次审核（shenhe: "待审核" → "已审核"）

```
审核机制（人/AI/算法）读取父记录
    ↓
JSON.parse(wznr) 拿到 blocks
    ↓
调用 Fsj12wei.createBlocks(parsedJson, { meta: {...} })
    ↓
子记录创建完成，fu/zi 关联建立
    ↓
调用 editRow 更新父记录：
  - shenhe: "待审核" → "已审核"
```

### 4.2 内容编辑（触发二次审核）

用户编辑已发布的内容后提交：

```
用户编辑内容 → 生成新 JSON
    ↓
调用 editRow 更新父记录：
  - shnr = 新 JSON（暂存待审核）
  - shenhe: "已审核" → "二次审核"（新内容待审核）
  - wznr 保持旧 JSON 不变（列表/详情仍显示旧内容）
```

**编辑期间的用户体验：**
- 列表页：仍显示旧内容（wznr），用户无感知
- 详情页：仍渲染旧内容（wznr JSON）
- 后台：新内容在 shnr 等待审核

### 4.3 二次审核通过（shenhe: "二次审核" → "已审核"）

```
审核机制读取 shnr 新 JSON
    ↓
（可选）删除旧的子记录
    ↓
调用 Fsj12wei.createBlocks 基于新 JSON 创建子记录
    ↓
调用 editRow 更新父记录：
  - wznr = shnr（新 JSON 替换旧 JSON）
  - shnr = ""（清空待审核字段）
  - shenhe: "二次审核" → "已审核"
```

### 4.4 审核驳回（可选流程）

```
审核机制驳回 shnr
    ↓
调用 editRow 更新父记录：
  - shnr = ""（清空待审核）
  - shenhe: "二次审核" → "已审核"（恢复为已审核，保留旧内容）
```

## 五、状态流转图

```
         发布
          │
          ▼
    ┌────────────┐
    │ shenhe=待审核 │ 待审核
    │ wznr=JSON  │ 列表不可见
    └────┬───────┘
         │ 首次审核通过
         │ (拆 JSON → 子记录)
         ▼
    ┌────────────┐
    │ shenhe=已审核 │ 已审核 ◀──┐
    │ wznr=JSON  │ 列表可见   │ 二次审核通过
    └────┬───────┘           │ (shnr → wznr)
         │ 用户编辑内容     │
         ▼                 │
    ┌────────────┐         │
    │ shenhe=二次审核│ 二次审核 │
    │ wznr=旧    │         │
    │ shnr=新    │ 列表显示旧│
    └────┬───────┘         │
         │ 审核通过 ────────┘
         │ 或驳回 → 清空 shnr, 保持 shenhe=已审核
```

## 六、列表/详情读取规则

### 6.1 列表页（首页文章列表）

**过滤条件**（必须加）：

```javascript
filters: [
  // 排除待审核内容
  { controlId: 'shenhe', dataType: 2, spliceType: 1, filterType: 6, value: '待审核' },
  // 排除已逻辑删除
  { controlId: 'shanchu', dataType: 2, spliceType: 1, filterType: 6, value: '1' }
]
```

**显示逻辑**：
- shenhe="二次审核" 和 "已审核" 都显示
- 都用 `wznr` 字段渲染摘要/预览（shenhe="二次审核" 时 wznr 是旧内容）

### 6.2 详情页

**读取字段**：`wznr`（当前生效版本）

```javascript
// 伪代码
var json = JSON.parse(data.wznr);
// 根据 json.blocks 渲染层级 UI
// （前端渲染逻辑下期实现）
```

**shenhe 状态对详情页无影响**：不管是 "二次审核" 还是 "已审核"，都读 wznr 渲染。

### 7.3 用户编辑内容（触发二次审核）

```javascript
callMingdaoAPI('https://api.mingdao.com/v2/open/worksheet/editRow', {
  worksheetId: 'shangpin',
  rowId: parentRowid,
  triggerWorkflow: false,
  getSystemControl: 'false',
  controls: [
    { controlId: 'shnr',   value: JSON.stringify(newContentObj) },
    { controlId: 'shenhe', value: '二次审核' }  // 进入二次审核
    // wznr 不改！保持旧内容展示
  ]
})
```

### 7.4 首次审核通过

```javascript
// 步骤1：读取父记录 wznr
var json = JSON.parse(parentData.wznr);

// 步骤2：调用 Fsj12wei.createBlocks 拆成子记录
Fsj12wei.createBlocks(json, {
  meta: {
    mingcheng: json.mingcheng,
    fabuzhe: parentData.fabuzhe,
    shangjia1: '1'
  }
}).then(function (results) {
  // 步骤3：更新父记录 shenhe="已审核"
  callMingdaoAPI('https://api.mingdao.com/v2/open/worksheet/editRow', {
    worksheetId: 'shangpin',
    rowId: parentRowid,
    controls: [
      { controlId: 'shenhe', value: '已审核' }
    ]
  });
});
```

### 7.5 二次审核通过

```javascript
// 步骤1：读取父记录 shnr
var newJson = JSON.parse(parentData.shnr);

// 步骤2：（可选）删除旧的子记录
// ...

// 步骤3：基于新 JSON 重建子记录
Fsj12wei.createBlocks(newJson, { meta: {...} }).then(function () {
  // 步骤4：shnr → wznr, 清空 shnr, shenhe="已审核"
  callMingdaoAPI('https://api.mingdao.com/v2/open/worksheet/editRow', {
    worksheetId: 'shangpin',
    rowId: parentRowid,
    controls: [
      { controlId: 'wznr',   value: parentData.shnr },
      { controlId: 'shnr',   value: '' },
      { controlId: 'shenhe', value: '已审核' }
    ]
  });
});
```

## 八、迁移说明

### 8.1 旧发布逻辑 vs 新发布逻辑

| 维度 | 旧方案 | 新方案 |
|------|-------|-------|
| 发布动作 | `Fsj12wei.createBlocks` 串行创建 N 条 | `addRow` 一次创建 1 条 |
| 发布速度 | N × 0.6-1.5 秒 | 0.6-1.5 秒 |
| 正文存储 | 分散在子记录 `neirong` | 父记录 `wznr` JSON |
| 列表可见 | 发布即可见 | 审核通过后可见 |
| 内容编辑 | 复杂（改子记录） | 简单（更新 shnr） |
| 前端渲染 | 读 mdnr/wznr 文本 | 读 wznr JSON 渲染层级 UI |

### 8.2 历史数据迁移

已发布的内容（旧 createBlocks 创建的）：
- 父记录 `wznr` 可能为空或存了 HTML
- 需要补充迁移脚本：从子记录反序列化出 JSON 写回 `wznr`
- 并将 `shenhe` 设为 `"已审核"`（视为已审核）

### 8.3 publish.js 改动要点

需要修改 `handleSubmit` 函数：

```diff
- // 旧逻辑：调用 Fsj12wei.createBlocks 直接拆成子记录
- Fsj12wei.createBlocks(contentObj, { meta: {...} })

+ // 新逻辑：只创建父记录，wznr 存 JSON
+ callMingdaoAPI(addRow, {
+   controls: [
+     ...,
+     { controlId: 'wznr', value: JSON.stringify(contentObj) },
+     { controlId: 'shenhe', value: '待审核' }
+   ]
+ })
```
