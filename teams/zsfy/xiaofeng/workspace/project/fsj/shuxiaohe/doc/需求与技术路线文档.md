## 一、项目概述

### 1.1 项目背景

**同檐er 2.0** 是一个校园零食即时零售小程序，主打"盒子价先享后付"模式。

本项目同时作为**通用商城 SPA 2.0 架构**的标杆实现，目标是建立一套**可复用的电商底层**，后续可快速复制到其他商家项目。

### 1.2 核心定位

| 维度 | 定位 |
|------|------|
| 产品层面 | 校园零食零售，盒子价先享后付 |
| 技术层面 | 通用商城 SaaS 架构的首个落地项目 |
| 架构层面 | 小程序原生 + Webview SPA 混合模式 |

### 1.3 核心优势

1. **盒子价专属低价** - 引导用户优先选择先享后付
2. **余额仅用于盒子价** - 唯一限制为起送门槛
3. **先享后付** - 0元下单 → 先拿货 → 吃了再付
4. **积分通用** - 所有消费 1元=1积分
5. **低代码可复制** - 核心表 + JSON 扩展 = 新项目快速上线

## 二、业务需求

### 2.1 目标用户

| 角色 | 功能 |
|------|------|
| 校园学生（买家） | 浏览商品、加购物车、下单、支付、使用余额/积分、管理盒子 |
| 配送员（履约/库存） | 配货出库、确认送达、退货回收、管理学生订单 |
| 管理员（后台运营） | 商品管理、订单管理、用户管理（HAP 后台） |

### 2.2 核心业务流程

```
用户浏览商品 → 加入购物车 → 选择支付模式 → 下单
    │
    ├── 全额立即支付 → 微信支付 → 配货 → 取货 → 完成
    │
    └── 盒子价先享后付 → 0元下单 → 配货送达 → 进入盒子
            │
            ├── 用户打开盒子 → 看到商品格子（铺开来）
            ├── 点击商品 → 高亮选中（可多选）
            ├── 查看详情 → 展开面板查看商品清单
            ├── 立即支付 → 选择支付方式（余额/微信/组合）
            └── 支付成功 → 商品标记已开封 ✓
```

### 2.3 支付规则

| | 盒子价先享后付 | 全额立即支付 |
|---|---|---|
| 付款时机 | 先拿货，后付款 | 下单时立即付款 |
| 支付金额 | 盒子价（低价） | 全额售价 |
| 可用余额 | ✅ | ❌ |
| 起送门槛 | ✅ 必须满足 | ❌ 无 |
| 获取积分 | ✅ | ✅ |

### 2.4 盒子订单

**核心概念：**
- **铺开来陈列** - 买了5个猫条，盒子里显示5个格子
- **只展示图片** - 不显示名称和价格，保持视觉简洁
- **选中高亮** - 点击切换橙色边框+✓角标
- **批量支付** - 多选商品 → 计算总价 → 支付
- **支付 = 开封** - 支付成功后商品标记已开封
- **同SKU不同批次价格不同** - 每批独立锁价

**商品状态：**
| 状态 | 视觉 | 操作 |
|------|------|------|
| 待送达 | 灰色遮罩"待送达" | 不可操作 |
| 已送达 | 正常显示 | 可点击选中 |
| 已开封 | 半透明置灰 | 不可操作 |

**页面组件规范：**
```javascript
class 页面名 {
    constructor(container) {
        this.container = container;
    }
    async init() { /* 加载HTML、绑定事件、加载数据 */ }
    destroy() { /* 清理定时器、事件监听 */ }
```

## 四、通用商城 SaaS 架构

### 4.1 设计原则

| 原则 | 说明 |
|------|------|
| **核心表固定** | 所有项目共用同一套表结构 |
| **JSON 扩展灵活** | 差异化信息存 JSON，不同项目按需扩展 |
| **多租户** | 通过 `project_id` 区分不同项目 |
| **API 统一** | 通用接口 + 项目特有接口（中间件注册） |
| **前端个性化** | 核心逻辑复用，UI 按需定制 |

### 4.2 通用核心表（9张）

| 表名 | 用途 | 关键字段 |
|------|------|----------|
| `users` | 用户表 | 余额、积分、用户类型 |
| `products` | 商品表 SPU | 名称、分类、主图 |
| `skus` | SKU表 | 规格、价格、库存、条形码 |
| `categories` | 分类表 | 名称、父级、排序 |
| `orders` | 订单主表 | 订单号、状态、金额、支付 |
| `order_items` | 订单明细表 | 商品快照、单价、数量、状态 |
| `payments` | 支付记录表 | 支付方式、金额、交易号 |
| `points_log` | 积分记录表 | 变动类型、来源、余额 |
| `inventory_log` | 库存变动日志 | 变动类型、前后库存 |

### 4.3 差异化处理方式

**方式一：JSON 扩展字段（简单差异化）**

所有核心表都有 `extra` 字段（JSON），不同项目按需存放。

```json
// 同檐er（校园项目）订单 extra
{
  "dormitory": "梅园1舍301",
  "school": "重庆建筑科技职业学院",
  "hexi_items_count": 5
}

// 餐饮项目订单 extra
{
  "table_number": "A12",
  "dine_type": "堂食",
  "special_notes": "少辣"
}
```

**方式二：项目自定义表（复杂差异化）**

当差异化信息结构复杂、需要独立查询时，建项目专属表。

| 项目 | 自定义表 |
|------|----------|
| 同檐er | `deliveryman_bind`（配送员绑定）、`dormitory`（寝室表） |
| 餐饮 | `table`（餐桌表）、`reservation`（预约表） |
| 零售 | `store`（门店表）、`shelf`（货架表） |

**核心字段 vs 扩展字段 判断标准：**

| → 核心字段 | → extra JSON |
|---|---|
| 所有项目都需要 | 仅特定项目需要 |
| 需要筛选/排序 | 仅展示用 |
| 需要统计/聚合 | 结构不固定 |
| 会被多表关联 | 可能嵌套多层 |

### 4.4 通用后端 API

**统一路由：** `/api/v1/{project_id}/...`

**通用接口：**
| 模块 | 接口 | 说明 |
|------|------|------|
| 商品 | `GET /products` | 商品列表 |
| 商品 | `GET /products/:id` | 商品详情 |
| 订单 | `POST /orders` | 创建订单 |
| 订单 | `GET /orders` | 订单列表 |
| 订单 | `POST /orders/:no/items/:id/open` | 开封确认 |
| 支付 | `POST /pay/wechat` | 微信支付 |
| 支付 | `POST /pay/balance` | 余额支付 |
| 积分 | `GET /points` | 积分明细 |
| 用户 | `POST /auth/login` | 微信登录 |

**项目特有接口（中间件注册）：**
```javascript
// 同檐er项目特有
router.post('/api/v1/tongyaner/dormitory/switch', dormitoryController.switch);

// 其他项目特有
router.post('/api/v1/other_project/table/reserve', tableController.reserve);
```

## 五、低代码/SaaS 逻辑

### 5.1 快速复制新项目流程

```
1. 新建项目配置
   └── project_id + 项目密钥

2. 配置通用功能
   ├── 商品分类
   ├── 支付方式（全额/盒子价）
   ├── 积分规则
   └── 配送方式

3. 配置差异化字段
   ├── 选择需要哪些 extra 字段
   └── 是否需要自定义表

4. 生成小程序
   ├── 复用核心代码
   └── 替换 UI 主题色/图标

5. 上线
```

### 5.2 可复用模块

| 模块 | 复用度 | 说明 |
|------|--------|------|
| 用户系统 | 100% | 登录、余额、积分 |
| 商品系统 | 100% | SPU+SKU、分类、搜索 |
| 订单系统 | 100% | 下单、状态流转 |
| 支付系统 | 100% | 微信、余额、组合支付 |
| 积分系统 | 100% | 获得、消耗、记录 |
| 库存系统 | 100% | 扣减、补货、日志 |
| 盒子订单 | 60% | 核心逻辑复用，UI 可定制 |
| 配送系统 | 40% | 校园配送特殊逻辑多 |

### 5.3 个性化配置

| 配置项 | 说明 | 存储位置 |
|--------|------|----------|
| 主题色 | 品牌色（按钮、高亮） | 项目配置表 |
| 起送门槛 | 盒子价最低金额 | 项目配置表 |
| 积分比例 | 消费1元=X积分 | 项目配置表 |
| 初始余额 | 新用户赠送金额 | 项目配置表 |
| 自定义字段 | 项目特有字段 | extra JSON Schema |

## 八、关键业务规则

### 8.1 余额规则
- 仅可支付盒子价订单
- 唯一限制：起送门槛
- 不可提现、转赠、兑换

### 8.2 积分规则
- 所有消费 1元=1积分
- 仅可抵扣盒子价订单
- 不可兑换余额、提现、转赠

### 8.3 盒子订单规则
- 下单后商品进入盒子（待送达）
- 送达后商品变为正常状态
- 用户勾选商品 → 批量支付 → 已开封
- 未开封商品可申请退货
- 同 SKU 不同批次价格独立

## 九、风险与注意事项

### 9.1 技术风险
| 风险 | 应对 |
|------|------|
| Webview 缓存 | 三层缓存禁用机制 |
| 跨域通信 | postMessage + URL 参数 |
| 明道云 API 限流 | 本地缓存 + 请求合并 |
| 微信支付回调 | 幂等处理 + 重试机制 |

### 9.2 业务风险
| 风险 | 应对 |
|------|------|
| 余额滥用 | 严格校验起送门槛 |
| 库存超卖 | 下单即扣减库存 |
| 数据一致性 | 事务 + 补偿机制 |
| 多项目数据混淆 | project_id 强制校验 |
