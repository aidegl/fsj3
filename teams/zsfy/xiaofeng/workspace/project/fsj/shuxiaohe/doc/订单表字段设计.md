# 通用商城 - 核心表结构设计方案

> 创建时间：2026-05-13
> 架构：核心表（通用固定） + JSON 扩展字段（差异化灵活）
> 目标：一套后端服务多项目，前端按需个性化

---

## 一、整体架构

```
项目标识 project_id
    │
    ├── 通用核心表（所有项目共用）
    │   ├── 用户表 users
    │   ├── 商品表（SPU）products
    │   ├── SKU表 skus
    │   ├── 订单主表 orders
    │   ├── 订单明细表 order_items
    │   ├── 支付记录表 payments
    │   ├── 积分记录表 points_log
    │   └── 库存变动日志表 inventory_log
    │
    └── 差异化处理
        ├── JSON 扩展字段（extra）→ 简单差异化
        └── 项目自定义表 → 复杂差异化（如校园项目的寝室表、配送员表）
```

## 三、差异化处理方式

### 3.1 方式一：JSON 扩展字段（推荐，简单差异化）

所有核心表都有 `extra` 字段（JSON），不同项目按需存放。

**例子 - 同檐er（校园项目）的订单 extra：**
```json
{
  "dormitory": "梅园1舍301",
  "school": "重庆建筑科技职业学院",
  "hexi_items_count": 5,
  "min_threshold_met": true
}
```

**例子 - 其他项目（餐饮项目）的订单 extra：**
```json
{
  "table_number": "A12",
  "dine_type": "堂食",
  "special_notes": "少辣"
}
```

### 3.2 方式二：项目自定义表（复杂差异化）

当差异化信息结构复杂、需要独立查询时，建项目专属表。

**例子 - 同檐er项目：**
- `deliveryman_bind`：配送员-学生绑定关系表
- `dormitory`：寝室表
- `box_config`：盒子价配置表（起送门槛等）

**例子 - 其他项目：**
- 各自建需要的表，通用后端不强制

## 五、通用后端 API 设计

### 5.1 统一路由前缀

```
/api/v1/{project_id}/...
```

所有 API 通过 `project_id` 区分项目，后端路由中间件自动注入项目上下文。

### 5.2 通用接口列表

| 模块 | 接口 | 说明 |
|------|------|------|
| 商品 | `GET /products` | 商品列表（支持分类筛选、搜索） |
| 商品 | `GET /products/:id` | 商品详情（含 SKU 列表） |
| SKU | `GET /skus/:id` | SKU 详情 |
| 分类 | `GET /categories` | 分类列表 |
| 订单 | `POST /orders` | 创建订单 |
| 订单 | `GET /orders` | 订单列表 |
| 订单 | `GET /orders/:no` | 订单详情 |
| 订单 | `POST /orders/:no/items/:id/open` | 开封确认 |
| 订单 | `POST /orders/:no/items/:id/refund` | 申请退货 |
| 支付 | `POST /pay/wechat` | 微信支付 |
| 支付 | `POST /pay/balance` | 余额支付 |
| 积分 | `GET /points` | 积分明细 |
| 用户 | `POST /auth/login` | 微信登录 |
| 用户 | `GET /user/profile` | 用户信息 |
| 库存 | `GET /inventory` | 库存查询 |
| 库存 | `POST /inventory/restock` | 补货 |

### 5.3 项目差异化 API

通过中间件注册项目特有的接口：

```javascript
// 同檐er项目特有接口
router.post('/api/v1/tongyaner/dormitory/switch', dormitoryController.switch);
router.post('/api/v1/tongyaner/delivery/bind', deliveryController.bind);

// 其他项目特有接口
router.post('/api/v1/other_project/table/reserve', tableController.reserve);
```

## 六、核心字段 vs 扩展字段 判断标准

| 满足以下任一 → 核心字段 | 否则 → extra JSON |
|---|---|
| 所有项目都需要 | 仅特定项目需要 |
| 需要作为筛选/排序条件 | 仅展示用 |
| 需要统计/聚合计算 | 结构不固定 |
| 会被多个表关联 | 可能嵌套多层 |
