## 二、核心业务

### 2.1 支付规则

| | 盒子价先享后付 | 全额立即支付 |
|---|---|---|
| 付款时机 | 先拿货，后付款 | 下单时立即付款 |
| 支付金额 | 盒子价（低价） | 全额售价 |
| 可用余额 | ✅ | ❌ |
| 起送门槛 | ✅ ¥10 | ❌ 无 |
| 获取积分 | ✅ 1元=1积分 | ✅ 1元=1积分 |

### 2.2 盒子订单流程

```
下单（0元） → 配货送达 → 商品进入盒子
    │
    ├── 盒子页面显示商品格子（铺开来）
    ├── 点击商品 → 高亮选中（可多选）
    ├── 查看详情 → 展开面板查看清单
    ├── 立即支付 → 选择支付方式
    └── 支付成功 → 商品标记已开封 ✓
```

**核心规则：**
- 支付成功 = 已开封
- 支持批量多选支付
- 商品格子只显示图片，不显示名称/价格
- 同 SKU 不同批次价格独立（下单时锁价）

### 2.3 商品状态

| 状态 | 视觉表现 | 可操作 |
|------|----------|--------|
| 待送达 | 灰色遮罩"待送达" | ❌ |
| 已送达 | 正常显示 | ✅ 可选中 |
| 已开封 | 半透明置灰 | ❌ |

## 四、数据架构策略

### 4.1 复用服世界通用数据

同檐er项目**不独立建表**，所有商品、订单、用户等核心数据统一存放在服世界的明道云 HAP 工作表中，通过 `shangjia_id` / `project_id` 区分数据归属。

```
服世界明道云 HAP（共享）
├── 商品表 → 同檐er的商品通过 shangjia_id 标记
├── 订单表 → 同檐er的订单通过 shangjia_id 标记
├── 用户表 → 同檐er的用户通过 shangjia_id 标记
└── ...
```

### 4.2 API 调用方式

| 方式 | 状态 | 说明 |
|------|------|------|
| ~~直接调用明道云 HAP（含密钥）~~ | 不推荐 | 密钥暴露，需迁移 |
| 通过 Coze Workflow 代理 | 推荐 | 密钥不暴露，统一复用服世界 API |

同檐er项目的前端（Webview / 小程序）应通过 **服世界 Coze Workflow** 调用明道云数据，而非直接调用明道云 API。

### 4.3 项目定制化处理

当同檐er有差异化需求时，通过以下方式处理：
- **extra JSON 字段**：简单差异化（如寝室信息、学校信息）
- **项目自定义表**：复杂差异化（如配送员绑定表、寝室表）

### 4.4 全局数据价值

同檐er数据存放在服世界通用表中，支持：
- 跨商家消费趋势分析
- 用户画像建模（通过分类标签）
- 热门商品/品类推荐

当用户同意时，其数据可参与全局分析；需要隐私隔离的用户，通过 extra JSON 字段隔离。

## 六、业务规则备忘

### 6.1 余额规则
- 仅可支付盒子价订单
- 唯一限制：起送门槛 ¥10
- 不可提现、转赠、兑换

### 6.2 积分规则
- 所有消费 1元=1积分（含初始余额消费）
- 仅可抵扣盒子价订单
- 不可兑换余额、提现、转赠

### 6.3 盒子订单规则
- 下单后商品进入盒子（待送达）
- 送达后商品变为正常状态
- 用户勾选商品 → 批量支付 → 已开封
- 未开封商品可申请退货
- 同 SKU 不同批次价格独立锁价
