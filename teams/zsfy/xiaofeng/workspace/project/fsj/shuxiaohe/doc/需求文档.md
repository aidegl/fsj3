# 同檐er 2.0 需求文档

## 1. 项目概述

### 1.1 项目背景

- **项目名称**：同檐er 2.0
- **项目类型**：微信小程序（原生开发）
- **技术栈**：HAP 明道云（后端数据）、宝塔（微信登录/支付）
- **目标用户**：校园学生（买家）、配送员（履约/库存）、管理员（后台运营）
- **核心场景**：校园零食即时零售，主打盒子价先享后付模式，兼顾全额支付小额需求

### 1.2 产品定位

以首页为核心下单入口，用户每次新增零食采购均可直接从首页发起；全商品支持「全额立即支付」「盒子价先享后付」双模式。

**核心优势**：

1. 盒子价专属低价，引导用户优先选择；
2. 账户余额仅可支付盒子价订单，唯一限制为起送门槛；
3. 余额/微信支付同等累计积分（1元=1积分，含初始余额）；
4. 盒子价订单先取货、扫码入库、吃多少付多少，未食用商品可退货；
5. 全额订单无起送限制，满足小额即时采购需求。

### 1.3 目标用户

| 角色 | 功能 |
|------|------|
| 校园学生（买家） | 浏览商品、加购物车、下单、支付、使用余额/积分 |
| 配送员（履约/库存） | 切换寝室、申请补货、配货、出库、管理寝室库存 |
| 管理员（后台运营） | 商品管理、订单管理、用户管理（HAP 后台） |

## 2. 核心业务规则

### 2.1 支付规则总览

| 订单类型 | 支付方式 | 余额使用 | 积分获取 | 起送门槛 |
|----------|----------|----------|----------|----------|
| 盒子价订单 | 余额支付、微信支付（组合支付） | ✅ 可使用，仅受起送门槛限制 | ✅ 消费1元=1积分（含初始余额） | ✅ 必须满足最低起送金额（后台可配置） |
| 全额支付订单 | 微信支付 | ❌ 不可使用 | ✅ 消费1元=1积分 | ❌ 无任何起送限制 |

### 2.2 账户余额核心规则

1. **使用范围**：仅可抵扣/支付盒子价订单的应付金额，全额订单绝对不可使用；
2. **使用限制**：唯一限制为盒子价订单是否满足最低起送金额，满足则可全额/部分使用余额，不满足则无法创建盒子价订单；
3. **获取渠道**：新用户注册赠送（初始余额5元）、平台活动发放、售后退款返还；
4. **其他限制**：不可提现、不可转赠、不可兑换余额、不可用于全额订单。

### 2.3 积分核心规则

1. **获取逻辑**：所有消费行为（余额支付、微信支付，含初始余额消费），均按 1元=1积分 累计；
2. **使用范围**：仅可抵扣盒子价订单应付金额；
3. **核心红线**：积分不可兑换余额、不可提现、不可转赠；
4. **获取时效**：消费完成/订单结清后，实时发放至用户积分账户。

### 2.4 双模式下单规则

1. **整单统一**：每笔订单仅可选择一种模式，不可混合盒子价/全额支付计价；
2. **自由选择**：用户每次下单均可自主选择，无强制绑定；
3. **入口统一**：所有下单操作均从首页发起，购物车结算页选择模式。

### 2.5 履约与结算规则

1. **盒子价订单**：下单0付款 → 配货出库 → 用户扫码入库 → 按实消费确认 → 余额/微信支付结清；
2. **全额订单**：下单即时付款 → 配货出库 → 用户取货 → 订单完成；
3. **余额抵扣优先级**：盒子价订单付款时，默认优先使用账户余额，余额不足时用微信支付补足差额。

## 3. 功能需求

### 3.1 核心功能模块（优先级 P0）

| 模块 | 功能描述 | 核心规则 |
|------|----------|----------|
| 首页下单入口 | 全平台核心下单入口，用户每次新增采购均从首页发起 | 无前置限制，随时可下单 |
| 商品双价格体系 | 每个商品配置「全额售价」「盒子价」，盒子价更低 | 盒子价为先享后付专属价，全额价为即时支付价 |
| 购物车管理 | 商品加购、数量调整、价格计算、规则校验 | 双价格联动，实时计算全额/盒子价合计，支持滚动查看全部商品 |
| 双模式结算 | 结算页二选一：全额支付/盒子价先享后付 | 整单统一模式，盒子价订单校验起送门槛 |
| 余额使用管控 | 仅盒子价订单可使用余额，仅受起送门槛限制 | 页面实时展示余额可用状态，不满足则禁用 |
| 积分累计规则 | 所有消费1元=1积分（含初始余额） | 消费完成后实时到账，无门槛 |
| 扫码入库 | 盒子价商品扫码后自动录入「盒子订单」 | 校验订单归属，防重复扫码，解锁页面入口 |
| 盒子订单管理 | 无有效商品时入口置灰，有商品时可进入 | 仅展示已入库商品，支持消费确认、付款、退货 |
| 订单全生命周期 | 全额/盒子价订单状态独立流转 | 支持配货、出库、入库、结清、退货等状态 |
| 配送员履约 | 库存管理、配货出库、扫码核销、退货回收 | 盒子价订单出库生成专属二维码，可查看管理学生的所有订单 |

### 3.3 商品展示

- **分类筛选**：全部、零食、饮品、日用品、主食（分类数据从 HAP 动态获取，支持新增分类自动显示）
- **商品卡片**：商品图片、商品名称、全额售价（灰色）、盒子价（红色突出）、余额可付标签、一键加购按钮
- **展示方式**：淘宝/拼多多式 2 列网格布局

### 3.4 购物车功能

- **加入购物车**：点击加购按钮添加到购物车
- **数量调整**：+/- 按钮调整数量，带"请稍等"加载提示
- **实时计算**：
  - 单品小计 = 单价 × 数量
  - 购物车合计 = 所有单品小计之和（双价格分别计算）
- **删除商品**：数量为 0 时移除
- **防重复点击**：按钮置灰禁止连续点击
- **商品显示**：支持滚动查看全部已加购商品

### 3.5 双模式结算

#### 模式选择区

1. **全额立即支付**：标注「无起送门槛，不可用余额」（可点击查看介绍）
2. **盒子价先享后付**：标注「专属低价，可用余额支付，需满足起送门槛」（可点击查看介绍）

#### 规则提示区

- 选择盒子价：显示用户可用余额、最低起送金额（后台可配置）、差额提示（若未满足）
- 选择全额：隐藏余额相关内容，标注「不可使用余额」

#### 提交按钮

- 盒子价订单：未满足起送门槛 → 置灰 + 提示；满足 → 可点击
- 全额订单：无限制 → 可点击

### 3.6 盒子订单（原"我的盒子"）

#### 入口与状态

- **空状态**：未下单或无有效商品时，显示空状态页面（不显示商品列表）
- **待核销状态**：下单后商品显示为灰色，等待核销
- **已核销状态**：核销后商品变为正常颜色，可进行支付

#### 核销流程

1. 用户下单后，盒子订单页面显示灰色商品（含数量）
2. 配货员送达并点击确认，或用户扫码核销
3. 核销后商品变为正常状态，可进行消费确认和支付
4. **仅限核销**：盒子订单页面仅用于核销和支付，不能加购新商品

#### 退货功能

- 待消费商品支持「申请退货」
- 配送员上门取走后点击确认，盒子对应商品数量删除
- 每周二、周五上门回收未食用完的商品

### 3.7 配送员功能

#### 学生绑定机制

- 学生第一次注册必须填写学校、楼栋、寝室号
- 公司后台收到提醒，手动绑定该学生的配送员
- 后续该学生的所有订单默认由绑定的配送员配送

#### 配送员职责

- **查看管理学生的所有订单**（含盒子价订单与全额支付订单）
- **查看学生盒子订单详情**：配送员可查看所管理学生的盒子订单，包括：
  - 盒子内商品列表（名称、数量、核销状态）
  - 待核销商品（灰色状态）
  - 已核销商品（正常状态）
  - 退货申请记录
- 盒子价订单和全额支付订单均获得 50% 提成
- 配货出库后生成商品专属二维码
- 送达后点击确认
- 处理学生退货申请，上门回收核销

```
├── 配送员首页

├── 订单管理
│   ├── 全部订单（盒子价+全额支付）
│   ├── 待配货
│   ├── 待送达
│   └── 已完成

│   ├── 选择学生查看其盒子订单
│   ├── 盒子内商品详情

│   │   ├── 核销状态（待核销/已核销）
│   │   └── 支付状态
│   └── 退货处理
└── 库存管理
    ├── 入库/出库操作
    └── 库存盘点
```

### 3.8 登录权限管控

#### 未登录状态

- 可浏览首页商品
- 点击「我的订单」「充值」等功能时，跳转到登录/注册页面
- 「退出登录」按钮隐藏，不显示
- 盒子订单入口可点击，但显示登录引导

#### 已登录状态

- 显示用户信息、余额、积分
- 「退出登录」按钮显示
- 所有功能正常使用

### 3.9 数据加载状态

- **下拉刷新**：显示 loading 动画
- **上拉加载更多**：显示 loading 动画
- **按钮点击**：显示"请稍等"提示，按钮置灰防重复点击

### 3.10 库存管控

- **商品规格维度管理库存**：每个商品规格独立库存
- **购买数量限制**：设置限购数量
- **超限提示**：购买数量超过库存或限购时，弹出"超出限购数或商品库存上限"
- **实时同步**：支付成功后立即扣减库存

## 9. 补充说明
