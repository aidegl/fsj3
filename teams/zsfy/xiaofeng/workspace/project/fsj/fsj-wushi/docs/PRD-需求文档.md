## 一、背景与定位

Agent 的 12 维数据（技能/想法/项目/交流/规则/价值/目标/计划/信息/人脉/仓/复盘）全部存在 HAP `shangpin` 表，以「五事骨架」（`五事-<agent名>` → 道/天/地/将/法/时间记事）为树根组织。目前只能靠 agent 们通过 skills 读写，**没有可视化界面**。

**五事系统 = agent 12 维数据的可视化维护台**：看得见自己的数据树、改得动每个节点、按维度着色一目了然。

## 二、数据模型

### 2.1 数据源

| 项 | 值 |
|---|---|
| 表 | `shangpin`（`6a03ceaa7e29abcb297cbdfc`） |
| 接口 | 复用 hap-proxy：`https://100000whys.cn/obj`（all-targets / record-add / record-update / record-delete） |
| 过滤 | **`fabuzhe = <agent rowid>`**（客户端过滤，与 objectives 同模式） |
| 排序 | 同层按 `quanzhong` 升序（拖动改写） |

### 2.2 五事骨架（每个 agent 一套，只建一次）

```
五事-<agent名>（顶根，fu=空，sew=1技能）
├── 道（准则层）
├── 天（任务层）
├── 地（资源层）
├── 将（能力层）
├── 法（行动层）
└── 时间记事（时间线入口）
```

- 骨架节点由 agent 在 HAP 侧维护（见 创建数据指南.md §四·五），本系统**只读展示 + 允许编辑其内容**；**骨架节点（道/天/地/将/法/时间记事/五事根）禁止删除**（前端拦截 + 提示）

## 四、交互规则

1. **跨维度父子合法**：sew 只描述节点自身维度，父子可跨维度（天(1技能) 下挂 7目标 下挂 8计划）——与创建数据指南一致
2. **新建默认继承**：sew 默认=父节点 sew；若父为骨架节点（如 天=1技能），默认 8计划（天是任务层的常识默认），仍可改
3. **骨架保护**：`五事-*`、`道`、`天`、`地`、`将`、`法`、`时间记事`（判定：五事根的直接子节点 + 五事根本身）不显示删除按钮
4. **wznr 选填**：前端不做 wznr 必填校验（2026-09-03 定：必填是给 agent 的创建纪律，见 fsj-skills-open 文档，UI 不拦）
5. **保存反馈**：乐观更新 + toast「✓ 已自动保存」，失败标红可重试

## 五、技术方案

- 零依赖原生 JS ES Module SPA（同 objectives 三分离传统）
- 接口全走已部署 hap-proxy（`https://100000whys.cn/obj`），**零新增端点、零本地进程**
- 拖动排序：HTML5 DnD，落点后重算同层 quanzhong（步长 10），批量 record-update
- 颜色单源：`docs/12维颜色.json` → field-ids.js 内联同值（注释指明单源出处）
