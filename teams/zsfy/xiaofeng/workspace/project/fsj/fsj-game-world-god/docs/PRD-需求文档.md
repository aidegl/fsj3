## 六、技术架构

### 6.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 渲染 | Canvas 2D 原生 | 零依赖、团队三分离传统、本量级性能足够 |

### 6.3 渲染层次（自下而上）

```
① 地图背景（拼接块，每块独立资产）
② 块边界 + 标签
③ 必读段数据点（散布的圆标）
④ 远程 agent（模式色圆标 + 首字 + 名牌 + 朝向点）
⑤ 本地玩家（高亮描边 + 名牌）
⑥ HUD 层（坐标/状态/时间）
```

## 七、HD 渲染层设计

### 7.1 与像素渲染的区别

| | 像素渲染（废弃） | HD 渲染（本产品） |
|---|---|---|
| 素材 | 16×16 像素 tile，调色板限色 | 高清图片，不限色 |
| 缩放 | `imageSmoothing = false`（硬边） | 高质量 bicubic |
| 角色 | 40×40 精灵图（正面/眨眼帧） | 高清圆标 + 首字（立绘就绪后换图） |
| 地图 | tile 拼接（48×48 格） | 拼接大图块（每块独立资产） |

### 7.2 核心原则

> **数据只存一份（HAP），显示形态由渲染层决定。** 不预生成多尺寸文件，不维护像素版/高清版双份素材。

### 7.3 HD 角色渲染规格

```
本地玩家：
  半径 16px 圆标 + 模式色填充 + 首字白字
  选中时金色描边 + 名牌
  朝向指示点（金色小圆，位于移动方向）

远程 agent：
  半径 14px 圆标 + 模式色填充 + 首字白字
  名牌显示名字 + 当前状态标签

立绘模式（yxjszm/bm/cm 有图后）：
  替换圆标为立绘图片（等比缩放，FILL 裁切）
  四向行走：正面/背面/侧面 三帧切换
```

## 十、验收标准

1. 打开页面 3 秒内：地图渲染 + 角色出现 + 面板就绪
2. 方向键移动流畅（60fps），移动时 WS 实时广播
3. 双开互见：两个浏览器窗口各选不同 agent，互见移动
4. 必读段与成员表 bdwznr 一致
5. 控制台无红错；断 WS 自动重连
6. 认知模式色环正确显示每个 agent 的主模式
7. 天道路由条实时显示在线 agent 数量和状态

## 十一、风险

| 风险 | 概率 | 对策 |
|---|---|---|
| WS 服务器不稳定 | 低 | ws-bus 自动重连 + 断线队列 |
| HAP 代理限流 | 低 | 本地缓存 + 批量查询 |
| AI 立绘质量不达标 | 中 | 多轮 prompt 迭代，保底用圆标模式 |
| 多 agent 同时在线 WS 消息量大 | 低 | 150ms 节流 + 服务端广播限频 |
