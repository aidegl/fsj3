# 首页可配置组件系统架构文档

> 商家通过管理后台可视化配置首页布局，前端根据 JSON 配置动态渲染组件。

---

## 一、概述

### 1.1 背景

当前 webview-spa2.0 项目的首页（`js/pages/home.js`）采用硬编码方式，包含三个固定区块：轮播图（banner-swiper）、分类导航（category-nav）、文章列表（article-list）。所有组件类型、顺序、样式均写死在代码中，商家无法自定义。

项目已有 TabBar 配置机制，商家后台返回的 `shangjia` 数组结构如下：

```json
[
  {"name":"首页","sort":"0","page":"home","mode":"1","url":"https://.../?shangjia=xxx"},
  {"name":"盒子","sort":"1","page":"custom","icon":"hezi","url":"https://.../hezi.html"},
  {"name":"我的","sort":"4","page":"mine"}
]
```

其中 `mode: "0"` 表示内置 SPA 页面（无外部 URL），`mode: "1"` 表示外部 webview 地址。

**本方案的核心设计：对于 `mode: "0"` 的内置页面，`url` 字段不存外部地址，而是直接存放该页面的组件配置 JSON 对象。**

### 1.2 配置结构示例

```json
[
  {
    "name": "首页",
    "sort": "0",
    "page": "home",
    "mode": "0",
    "url": {
      "home_sections": [
        { "type": "banner_swiper", "config": { ... } },
        { "type": "feature_list", "config": { ... } },
        { "type": "content_list", "config": { ... } }
      ]
    }
  },
  {
    "name": "我的",
    "sort": "4",
    "page": "mine",
    "mode": "0",
    "url": {
      "home_sections": [
        { "type": "feature_list", "config": { ... } },
        { "type": "content_list", "config": { "content_types": ["product"], "card_layout": "horizontal" } }
      ]
    }
  }
]
```

### 1.3 前端识别逻辑

```javascript
// app.js 中 updateTabBar 的 url 映射逻辑
url: (item.mode === '0' || item.mode === 0)
  ? (typeof item.url === 'object' ? item.url : null)   // 内置页面：保留组件配置 JSON
  : (item.url ? (item.url.match(/^https?:\/\//) ? item.url : 'https://' + item.url) : null);  // 外部页面：URL 字符串
```

- `mode: "0"` + `url` 是对象 → 内置页面，`url` 存组件配置
- `mode: "0"` + `url` 是字符串/空 → 内置页面，无自定义配置，使用默认布局
- `mode: "1"` + `url` 是字符串 → 外部 webview 地址

### 1.4 设计目标

- 商家通过管理后台的可视化拖拽界面配置首页，无需触碰 JSON 或代码
- 前端根据配置 JSON 动态渲染首页，组件类型和顺序完全由配置驱动
- 每个组件类型有清晰的 `type` 标识符和专属 `config` 对象
- 组件配置与明道云数据源建立明确映射关系
- 架构可扩展，后续新增组件类型只需注册渲染器

### 1.5 核心概念

```
商家配置 (merchant config)
  └── home_sections: [   ← 数组顺序即页面从上到下的渲染顺序
        { type: "banner_swiper", config: {...} },
        { type: "feature_list", config: {...} },
        { type: "content_list", config: {...} },
        ...
      ]
```

## 二、JSON Schema 定义

### 2.1 根配置结构

```json
{
  "home_sections": [
    {
      "type": "<组件类型>",
      "config": { ... },
      "hidden": false
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `home_sections` | array | 是 | 组件区块数组，顺序决定渲染顺序 |
| `type` | string | 是 | 组件类型标识符（见 2.2） |
| `config` | object | 是 | 组件专属配置 |
| `hidden` | boolean | 否 | 临时隐藏该区块（默认 false） |

### 2.2 组件类型枚举

| type 值 | 中文名 | 说明 |
|---------|--------|------|
| `search_box` | 搜索框 | 顶部搜索栏，支持组织切换 |
| `banner_swiper` | 轮播图 | 展示图片轮播 |
| `feature_list` | 功能列表 | 网格快捷入口 |
| `content_list` | 内容列表 | 商品/文章/任务等列表 |

### 2.3 search_box 配置

```json
{
  "type": "search_box",
  "config": {
    "show_org_switch": true
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `show_org_switch` | boolean | 否 | 是否显示左侧组织切换下拉，默认 false（不显示） |

**UI 布局**：

```
┌──────────────────────────────────────────┐
|  [▼ 组织]  |  请输入要搜索的内容          |  ← 输入框撑开剩余宽度
└──────────────────────────────────────────┘
```

- 左侧：组织切换下拉（仅 `show_org_switch: true` 时显示），带三角形 `▼` 图标
- 右侧：搜索输入框，placeholder 固定为 `"请输入要搜索的内容"`，输入框撑开剩余宽度
- `show_org_switch: false` 时，不显示左侧组织切换，输入框占满整行

### 2.4 banner_swiper 配置

```json
{
  "type": "banner_swiper",
  "config": {
    "title": "精选推荐",
    "source_type": "article",
    "source_filter": {},
    "max_items": 5,
    "autoplay_interval": 4000,
    "click_action": "navigate_detail"
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | 否 | 区块标题（显示在轮播上方，可为空） |
| `source_type` | string | 是 | 图片来源：`"article"` / `"product"` / `"custom"` |
| `source_filter` | object | 否 | 按分类/标签过滤（source_type 为 article 或 product 时有效） |
| `max_items` | number | 否 | 最大展示数量，默认 5 |
| `autoplay_interval` | number | 否 | 自动播放间隔（毫秒），默认 4000 |
| `click_action` | string | 否 | 点击行为：`"navigate_detail"` / `"open_url"` / `"none"`，默认 `"none"` |

**source_filter 结构**（当 source_type = "article"）：
```json
{ "category": "技术" }
```

**source_filter 结构**（当 source_type = "product"）：
```json
{ "category": "饮品", "tags": ["新品"] }
```

**source_filter 结构**（当 source_type = "custom"）：
```json
{
  "items": [
    { "image_url": "https://...", "title": "...", "link_url": "https://...", "link_type": "page" }
  ]
}
```

### 2.5 feature_list 配置

功能列表的数据**来自明道云功能表**，不在 JSON 配置中硬编码 items。JSON 只控制是否展示：

```json
{
  "type": "feature_list",
  "config": {
    "show_feature_list": true,
    "title": "常用功能",
    "columns": 4
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `show_feature_list` | boolean | 是 | 是否显示功能列表，`true` 则从明道云功能表拉取数据 |
| `title` | string | 否 | 区块标题 |
| `columns` | number | 否 | 每行显示列数，默认 4 |

功能列表的具体 items 由 `FsjApi.getFeatureList()` 从明道云功能表（别名 `gongnengbiao`）查询：
- 按商家过滤（`shangjia` 字段，dataType: 29，filterType: 24）
- 按明道云后台内置排序（`listType: 1`）
- `icon` 字段为附件类型，取 `DownloadUrl` 显示图标
- `url` 字段为跳转链接（可为空表示内置页面路由）

### 2.5.1 明道云功能表结构

| 字段别名 | 类型 | 说明 |
|---------|------|------|
| `mingcheng` | 文本框 | 功能名称（显示文字） |
| `icon` | 附件 | 功能图标（取 DownloadUrl 渲染，建议 32x32 或等比例） |
| `url` | 文本框 | 跳转链接：有值时走外部 webview，为空时走内置页面路由（根据 label 判断） |
| `shangjia` | 关联记录 | 关联商家表，用于按商家过滤 |

### 2.6 content_list 配置

```json
{
  "type": "content_list",
  "config": {
    "title": "为你推荐",
    "content_types": ["product"],
    "card_layout": "horizontal",
    "items_per_load": 10,
    "sort_by": "default",
    "category_filter": [],
    "show_task_button": true
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | 否 | 区块标题 |
| `content_types` | array | 是 | 内容类型数组：`"product"` / `"article"` / `"task"` / `"points_product"` |
| `card_layout` | string | 是 | 卡片布局：`"horizontal"`（横排，左图右文）/ `"vertical"`（竖排，上图下文） |
| `items_per_load` | number | 否 | 每页加载数量，默认 10 |
| `sort_by` | string | 否 | 排序方式：`"default"` / `"price_asc"` / `"price_desc"` / `"weight_desc"` / `"newest"`，默认 `"default"` |
| `category_filter` | array | 否 | 分类过滤数组（为空表示不限分类） |
| `show_task_button` | boolean | 否 | 是否在列表顶部显示"接单任务"筛选按钮，默认 false |

**content_types 组合说明**：

- 单类型（如 `["product"]`）：列表只渲染一种内容，使用对应的专用卡片模板
- 多类型混合（如 `["product", "article"]`）：列表交替或按权重混合渲染，每个卡片带 `content_type` 标识以选择正确的模板
- `"task"` 类型：展示接单任务，点击可进入任务详情

## 四、数据流：前端如何消费配置

### 4.1 配置加载流程

```
[小程序打开 webview]
  │ URL 带 ?shangjia=<rowid>
  ▼
[App.fetchShangjiaConfig(rowid)]
  │ POST Coze Workflow (workflow_id: 7639306110034378761)
  ▼
[明道云商家表]
  │ 返回商家行数据，shangjia 字段包含 tab 数组
  │ 每个 tab 的 url 字段（mode=0时）为组件配置 JSON
  ▼
[App.updateTabBar(shangjia)]
  │ 识别 mode + url 类型：
  │   mode="0" + url是对象 → 保留为组件配置
  │   mode="1" + url是字符串 → 外部 webview 地址
  │ 存入 localStorage: fsj_shangjia_tabs
  ▼
[App.loadInitialPage()]
  │ 读取 tabBarConfig[0]（首个 tab）
  │ 若 url 是对象 → HomePage.init(url) 传入组件配置
  │ 若 url 是字符串 → switchToWebview(url)
  │ 否则 → switchPage(page)
  ▼
[首页渲染完成]
```

### 4.2 HomePage 重构后的初始化逻辑

```javascript
// js/pages/home.js 重构伪代码
HomePage = {
  config: null,

  init: function (pageConfig) {
    // pageConfig 即 tab 配置中的 url 字段（可能是组件配置对象）
    this.config = this.loadHomeConfig(pageConfig);
    this.renderSections();
  },

  loadHomeConfig: function (pageConfig) {
    // 1. 优先使用传入的组件配置（tab.url 是对象时）
    if (pageConfig && typeof pageConfig === 'object' && pageConfig.home_sections) {
      return pageConfig;
    }
    // 2. 回退到默认配置
    return this.getDefaultConfig();
  },

  renderSections: function () {
    var contentEl = document.getElementById('home-content');
    contentEl.innerHTML = '';  // 清空

    var self = this;
    this.config.home_sections.forEach(function (section, index) {
      if (section.hidden) return;
      var renderer = self.getRenderer(section.type);
      if (renderer) {
        renderer(section.config, contentEl, index);
      } else {
        console.warn('[HomePage] 未知组件类型:', section.type);
      }
    });

    // 渲染完后绑定全局事件（轮播手势、滚动加载等）
    this.bindEvents();
  },

  getRenderer: function (type) {
    var renderers = {
      'banner_swiper': this.renderBannerSwiper,
      'feature_list': this.renderFeatureList,
      'content_list': this.renderContentList
    };
    return renderers[type] || null;
  },

  getDefaultConfig: function () {
    // 保持向后兼容的默认配置
    return {
      home_sections: [
        { type: 'banner_swiper', config: { source_type: 'custom', source_filter: { items: [/* 默认3张 */] }, autoplay_interval: 4000, click_action: 'none' } },
        { type: 'content_list', config: { content_types: ['article'], card_layout: 'horizontal', items_per_load: 10 } }
      ]
    };
  }
};
```

### 4.4 各渲染器数据获取流程

**BannerSwiper 渲染器：**
- `config.source_type = "article"` → 调用 `FsjApi.getProductList()` + 过滤 `leixing === "文章"` → 提取 imageUrl 作为 banner 图片 → 渲染 banner-slides + banner-dots
- `config.source_type = "product"` → 调用 `FsjApi.getProductList()` + 过滤 category/tags → 提取 imageUrl
- `config.source_type = "custom"` → 直接使用 `config.source_filter.items`

**FeatureList 渲染器：**
- 纯静态渲染，无数据请求
- 渲染 func-grid + func-item
- 绑定点击事件：根据 link_type 调用 `App.switchPage` / `window.open`

**ContentList 渲染器：**
- `config.content_types = ["product"]` → 调用 `FsjApi.getProductList(page, pageSize, category)` → 使用产品卡片模板渲染
- `config.content_types = ["article"]` → 调用 `FsjApi.getProductList()` + 过滤 `leixing === "文章"` → 使用文章卡片模板渲染（复用现有 post-card 样式）
- `config.content_types = ["points_product"]` → 调用 `FsjApi.getPointsProductList()` → 使用积分商品卡片模板渲染
- `config.content_types = ["task"]` → 调用明道云接单任务表（需新增 worksheet ID 和 API 方法） → 使用任务卡片模板渲染
- 多类型混合 → 并行请求各类型数据 → 按权重或轮询方式合并 → 每项携带 `content_type` 标识选择对应模板

## 五、组件类型与明道云数据源映射

### 5.1 映射总表

| 内容类型 (content_type) | 明道云工作表 | worksheet ID | 过滤条件 | 关键字段 |
|------------------------|-------------|-------------|---------|---------|
| `product` | 商品 | `6a03ceaa7e29abcb297cbdfc` | `leixing !== "积分商城"` | zhutu, mingcheng, shoujia, jifen, spfl |
| `article` | 商品（同表） | `6a03ceaa7e29abcb297cbdfc` | `leixing === "文章"` | zhutu(封面), mingcheng(标题), miaoshu(摘要) |
| `points_product` | 商品（同表） | `6a03ceaa7e29abcb297cbdfc` | `leixing === "积分商城"` | zhutu, mingcheng, jifen(积分价) |
| `task` | 接单任务 | 待配置 | 按商家/状态过滤 | 待确认工作表 ID 和字段 |

### 5.2 商品类型详细说明

```
明道云字段      → 前端字段           → 用途
─────────────────────────────────────────────────
zhutu          → imageUrl           → 商品图 / 文章封面 / banner 图
mingcheng      → name               → 商品名 / 文章标题
shoujia        → price              → 售价
jifen          → boxPrice / points  → 积分价 / 积分消耗
spfl           → category           → 商品分类
quanzhong      → weight             → 排序权重
miaoshu        → description        → 描述/摘要
leixing        → leixing            → 类型标识（区分商品/文章/积分商品）
ptxz           → groupLimit         → 拼团人数上限
ptyh           → groupJoined        → 已报名人数
ptrq           → groupDeadline      → 拼团截止日期
```

### 5.3 banner_swiper 数据来源详解

**当 source_type = "article" 时：**
1. 调用 `FsjApi.getProductList()` 获取所有商品行
2. 过滤 `leixing === "文章"` 的行
3. 若 `source_filter.category` 有值，再按 `spfl` 分类过滤
4. 取前 `max_items` 条，用 `zhutu` 解析图片 URL
5. 点击时跳转到对应文章详情页（通过 rowid 构造 URL hash）

**当 source_type = "product" 时：**
1. 调用 `FsjApi.getProductList()` 获取商品行
2. 排除 `leixing === "文章"` 和 `leixing === "积分商城"`
3. 按 `source_filter.category` / `source_filter.tags` 过滤
4. 取前 `max_items` 条

**当 source_type = "custom" 时：**
1. 直接使用 `config.source_filter.items` 数组
2. 每项含 `image_url`、`title`、`link_url`、`link_type`

### 5.4 接单任务（task）数据源

接单任务目前尚未接入前端，需要：
1. 确认明道云中"接单任务"工作表的 worksheet ID
2. 确认关键字段名（任务标题、描述、奖励、状态、截止日期等）
3. 在 `FsjApi` 中新增 `getTaskList()` 方法
4. 在 `content_list` 渲染器中新增 task 卡片模板

建议在明道云任务表中设置以下字段：
- `task_title` - 任务标题
- `task_desc` - 任务描述
- `task_reward` - 奖励金额/积分
- `task_status` - 状态（待接单/进行中/已完成）
- `task_deadline` - 截止时间
- `task_image` - 任务封面图

## 六、扩展指南：如何新增组件类型

### 6.1 步骤

**第一步**：在 JSON Schema 中定义新 `type` 标识符和 `config` 结构

```json
{
  "type": "new_component_type",
  "config": { ... }
}
```

**第二步**：在 `HomePage.getRenderer()` 中注册渲染器

```javascript
getRenderer: function (type) {
  var renderers = {
    'banner_swiper': this.renderBannerSwiper,
    'feature_list': this.renderFeatureList,
    'content_list': this.renderContentList,
    'new_component_type': this.renderNewComponent  // ← 新增
  };
  return renderers[type] || null;
}
```

**第三步**：实现渲染器方法


### 6.2 扩展原则

1. **单一职责**：每个渲染器只负责一种组件类型的渲染
2. **配置驱动**：所有可变参数（数量、排序、过滤）都通过 config 传入
3. **数据解耦**：渲染器通过 FsjApi 获取数据，不直接调用 MingdaoYun API
4. **向后兼容**：当配置中不存在 `home_sections` 字段时，使用默认配置渲染
5. **容错处理**：未知 type 的 section 应跳过并打印 console.warn，不应阻塞其他组件渲染

## 七、配置在明道云中的存储方式

### 7.1 存储位置

组件配置存储在明道云**商家表**的 `shangjia` 字段中，作为 tab 配置数组的一部分：

```json
{
  "name": "首页",
  "sort": "0",
  "page": "home",
  "mode": "0",
  "url": {
    "home_sections": [
      { "type": "banner_swiper", "config": { ... } },
      { "type": "content_list", "config": { ... } }
    ]
  }
}
```

### 7.2 Coze 工作流适配

现有的商家配置工作流（`workflow_id: 7639306110034378761`）返回的 `shangjia` 数组中，每个 tab 的 `url` 字段根据 `mode` 有不同含义：

| mode | url 字段含义 |
|------|-------------|
| `"0"` + url 是 JSON 对象 | 内置页面，url 存组件配置 |
| `"0"` + url 是空/字符串 | 内置页面，无自定义配置 |
| `"1"` + url 是字符串 | 外部 webview 地址 |

### 7.3 默认行为

- 商家 tab 的 `mode: "0"` 且 `url` 为空 → 使用前端默认配置渲染
- 商家 tab 的 `mode: "0"` 且 `url` 为 JSON 对象 → 使用商家自定义组件配置
- 配置格式错误 → 回退到默认配置，并在 console 输出警告
