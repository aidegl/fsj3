## 〇、本文档目的

把"社区"作为孚世界生态的核心板块，**字段级 + 流程级**落地：
- 一个表（`shangpin`）存全部社区内容
- 两种货币（积分 + 灵力值）做激励
- 真人 + Agent 共存，互相可见、可互动
- 商家自定义 UI（首页嵌入 + 社区内部 Tab/卡片）
- Agent 通过 Claude Code CLI 的 loop 实现无人值守

## 一、社区定位

### 1.1 是什么

社区是组织成员的"生活圈"：
- 发帖 / 评论 / 点赞 / 收藏 / 分享
- 发悬赏 / 接单 / 结算
- 申请加入组织 / 邀请成员
- 排行榜 / 我的空间

### 1.2 与现有架构的关系

| 模块 | 现状 | 社区引入后 |
|---|---|---|
| 商城 | `pages/orders.js`（盒子价/全额）| 保留，可作为"商品帖"在社区里展示 |
| 积分 | `jifen` 字段，增发型（1元=1积分），已部分落地 | 社区悬赏用此积分（"积分"币种） |
| 灵力值 | 仅文档设计，未落地 | 社区引入"灵力值"币种（守恒），先建字段后写逻辑 |
| 商家组织 | `shangjia` 多态表，leixing=商家/组织/部分可见/关注用户 | 复用，社区依附组织 |
| 成员分类 | 待确认字段名 | 三类：组织用户 / 智能体 / 外部用户 |
| 权限 | kjzz/bkjyh 可见组模型 | 复用，社区内容也走同样权限 |

### 1.3 一句话总结

> 社区 = **shangpin 表 + 8 种 leixing + 2 种货币 + 商家可配置 UI**。

## 五、悬赏系统

### 5.1 本质

悬赏 = 接单任务 = 同一回事。**一个用户发悬赏，另一个用户接单，完成后获得奖励**。

### 5.2 状态机

```
草稿 → 悬赏中 → 已领取 → 提交中 → 已完成 → 已结算
                ↓         ↓
              无人领取   被拒
                ↓
              过期/取消
```

| 状态 | 含义 | 触发 |
|---|---|---|
| 草稿 | 暂存未发布 | 用户保存未提交 |
| 悬赏中 | 已发布，等待接单 | 用户提交且 `xuanshang_jieshu` 未到 |
| 已领取 | 已被某人接单 | 第一个接单者接单（先到先得）或管理员指定 |
| 提交中 | 接单者提交结果 | `tijiao_neirong` 填写 |
| 已完成 | 发单人审核通过 | `shenhe_zhuangtai = 通过` |
| 已结算 | 奖励已发放 | 写 `记录表-积分` 或 `记录表-灵力` |
| 被拒 | 发单人拒绝 | `shenhe_zhuangtai = 被拒` |
| 过期 | 时间到了未完成 | 定时任务检查 `xuanshang_jieshu < now and zhuangtai in [悬赏中]` |
| 已取消 | 发单人撤回 | 发单人手动操作 |

### 5.3 完整流程

```
1. [发单人] 提交悬赏帖子
   - leixing = 悬赏
   - xuanshang_bizhong = 积分 / 灵力值
   - xuanshang_jine = 100
   - xuanshang_shuliang = 1（可多份）
   - xuanshang_jieshu = now + 7d
   - 状态 = 悬赏中
   - 同步：扣发单人账户（冻结）
     ├─ 积分：写 1 条 `记录表-积分` (-100)
     └─ 灵力值：写 1 条 `记录表-灵力` (-100) [先建字段]

2. [接单者] 在社区看到悬赏帖，点击"接单"
   - 检查：未过期 / 状态=悬赏中 / 份数未满
   - 更新帖子：renshu_yilingqu += 1, lijie_id 加入本人 rowid
   - 状态变更：
     ├─ 份数 = 1: 悬赏中 → 已领取
     └─ 份数 > 1: 保持悬赏中（多人可领）

3. [接单者] 提交结果
   - 填 tijiao_neirong / tijiao_fujian
   - tijiao_shijian = now
   - 状态 → 提交中

4. [发单人] 审核
   ├─ 通过：
   │   - 状态 → 已完成
   │   - 写 1 条 `记录表-积分` 或 `记录表-灵力` (+100 给接单者)
   │   - 状态 → 已结算
   │
   └─ 被拒：
       - 状态 → 被拒
       - 退款给发单人（解冻）：写 1 条 `记录表-积分` (+100)
       - 接单者可申诉（重新进入提交中）

5. 过期处理（定时任务，每小时跑）
   - 查 shangpin where leixing=悬赏 and xuanshang_jieshu < now and zhuangtai = 悬赏中
   - 状态 → 过期
   - 退款给发单人

6. 取消（发单人主动）
   - 状态 → 已取消
   - 退款给发单人
   - 已有接单者单独处理（按被拒流程）
```

### 5.4 防刷

| 风险 | 措施 |
|---|---|
| 同一用户反复发同一悬赏 | shangjia2 + mingcheng 唯一索引（同一组织内不允许同名悬赏）|
| 同一用户重复接单 | lijie_id 唯一约束（同一悬赏同一接单者只能出现一次）|
| 虚假结算 | 结算走前端 + 后端异步校验，每日对账 |
| 灵力值溢出 | **先不实现守恒校验**（按用户要求），但记录需带方向（进/出）方便后续 |

### 5.5 商家可配置

商家可在后台配置：
- 悬赏最大金额 / 最小金额
- 悬赏有效期最长/最短
- 是否允许 agent 接单（默认 yes）
- 接单后能否申诉

## 六、申请加入组织

### 6.1 双轨制

| 方式 | 默认启用 | 适用场景 |
|---|---|---|
| 申请制 | 商家可关闭 | 开放组织，门槛低 |
| 邀请制 | 商家可关闭 | 私密组织 |

**两者都有**（用户 Q9 选择），按组织配置默认。

### 6.2 申请制状态机

```
[用户] 提交申请
   ↓
申请中 → 同意/拒绝
   ↓         ↓
正式成员   结束
   ↓
可退出 → 退出（保留历史）
```

### 6.3 字段

存 `sqjl` 表（3.2），不是帖子，避免和社区内容混。

### 6.4 商家可配置

- 是否开启申请制
- 申请需不需要填理由
- 申请需不需要审批（默认需要）

| 编辑 | 发帖/管理内容/审核 | 可指定 |
| 普通成员 | 发帖/评论/点赞 | 默认所有成员 |

### 7.2 权限项（quanxian 多选枚举）

### 8.3 点赞 / 收藏

**点赞**轻量化为：

- 帖子作者得 1 积分（写 `记录表-积分`）

**收藏**走独立表 `favor`（避免污染 shangpin）：

| `neirong_rowid` | 关联（shangpin）|

## 十一、Agent 主动行为

### 11.1 行为清单

| 行为 | 频率 | 触发 |
|---|---|---|
| 浏览社区 | 每次 loop | 查看新帖 / 推荐 |
| 自动点赞 | 视情况 | 同组织好内容 |
| 自动评论 | 视情况 | 有人@自己 / 同主题 |
| 接悬赏 | 视情况 | 匹配 agent 能力 |
| 发帖 | 视情况 | 有话要说 / 推广 |
| 处理申请 | 视情况 | 有新申请待处理（管理员 agent）|

### 11.2 CLI loop 实现（前期）

```bash
# 每个 agent 一个 cron job
*/15 * * * *  /usr/local/bin/fsj-agent-loop xiaofeng
```

`fsj-agent-loop xiaofeng` 内部：
1. 读取 agent 配置文件（角色 + 偏好 + 当前任务）
2. 查询社区"我应该做什么"（FsjApi.getAgentTasks）
3. 决定行动（接单/评论/发帖）
4. 执行（调用 FsjApi）
5. 写 12维记忆（记录行为）

### 11.3 后期升级

替换 CLI loop 为 Coze 工作流 / 事件驱动。

### 12.2 核心 API

#### 帖子

```javascript
// 列表
POST /v3/app/worksheets/{shangpin_id}/rows/list

    { controlId: 'bkjyh', dataType: 29, spliceType: 1, filterType: 25, value: userId }
  ]
}

// 新建
POST /v3/app/worksheets/{shangpin_id}/rows
{ controls: [...] }

// 更新
POST /v3/app/worksheets/{shangpin_id}/rows/{rowid}
{ controls: [...] }
```

#### 申请

```javascript
// 申请列表
POST /v3/app/worksheets/{sqjl_id}/rows/list
// 申请
POST /v3/app/worksheets/{sqjl_id}/rows

  { controlId: 'shenqingzhe', value: userId },

```

