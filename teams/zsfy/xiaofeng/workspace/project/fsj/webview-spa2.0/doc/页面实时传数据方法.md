## 方法一：URL 参数 + webview 重载（推荐，最可靠）

**原理**：小程序端通过 `setData` 改变 `<web-view>` 的 `src` URL（带 query 参数），H5 在新加载时读取参数。

**适用场景**：支付结果回调、登录状态注入、强制刷新页面

### 小程序端发送

```js
// wxApp/pages/webview/index.js - onShow 中
onShow: function () {
  var payResult = getApp().globalData.lastPaymentResult;
  if (payResult) {
    var currentUrl = this.data.url;
    var baseUrl = currentUrl.split('#')[0];  // 去掉 hash
    var sep = baseUrl.indexOf('?') === -1 ? '?' : '&';

    // 拼接 _pay 参数 + 时间戳（确保 URL 不同）
    var reloadUrl = baseUrl + sep + '_pay=' + encodeURIComponent(JSON.stringify(payResult)) + '&_ts=' + Date.now();

    this.setData({ url: reloadUrl });
    getApp().globalData.lastPaymentResult = null;
  }
}
```

### H5 端接收

```js
// webview-spa2.0/js/app.js - init 或 checkPaymentResult 中
checkPaymentResult: function () {
  var search = window.location.search;
  if (search && search.indexOf('_pay=') !== -1) {
    var result = JSON.parse(decodeURIComponent(
      search.split('_pay=')[1].split('&')[0]
    ));

    console.log('[App] 收到支付结果:', result);
    // 处理业务逻辑...

    // 清理参数，防止重复处理
    var cleanUrl = window.location.pathname + window.location.hash;
    window.history.replaceState(null, '', cleanUrl);
  }
}
```

**可靠性**：✅ 高 — 只要 URL 确实改变（带 `_ts` 时间戳），H5 必定重新加载并读取到参数

**注意**：
- 如果 base URL 相同，`setData` 可能不会触发 webview 重载（微信原生组件缓存），此时必须加 `_ts` 等随机参数
- 极端情况下 `setData` 也不生效，可改用 `wx.redirectTo` 重建页面

## 方法二：globalData + localStorage 跨页面共享

**原理**：小程序端的 `globalData` 和 `localStorage` 在所有页面间共享，H5 通过 `localStorage` 也能读写（同域 web-view 内）。

**适用场景**：支付结果暂存、用户身份持久化、商家配置缓存

### 小程序端写入

```js
// wxApp/pages/pay/index.js - 支付成功后
getApp().globalData.lastPaymentResult = {
  success: true,
  body: '商品名称',
  amount: '0.01',
  _needCreateOrder: true
};

// 同时写入 localStorage（H5 可读取）
wx.setStorageSync('fsj_paymentResult', JSON.stringify({
  success: true,
  body: '商品名称',
  amount: '0.01'
}));
```

### H5 端读取

```js
// webview-spa2.0 任意位置
var payResult = wx.getStorageSync('fsj_paymentResult');
// 或直接用 localStorage
var payResult = localStorage.getItem('fsj_paymentResult');
```

**可靠性**：✅ 高 — 写入立即生效，读取无延迟

**注意**：
- `globalData` 仅小程序端可用
- `localStorage` 在 web-view 中与小程序端**不共享**（H5 读自己的 localStorage，小程序读小程序的）
- 小程序端需用 `wx.setStorageSync` / `wx.getStorageSync`
- H5 端用 `localStorage.getItem` / `localStorage.setItem`

## 方法三：wx.miniProgram.postMessage（H5 → 小程序）

**原理**：H5 通过微信 JS-SDK 向小程序发送消息，小程序在 `<web-view>` 的 `bindmessage` 事件中接收。

**适用场景**：H5 触发登录跳转、请求 openid、通知小程序拉起支付

### H5 端发送

```js
// webview-spa2.0/js/bridge.js
if (window.wx && window.wx.miniProgram) {
  window.wx.miniProgram.postMessage({
    data: { type: 'requestOpenid' }
  });
}
```

### 小程序端接收

```js
// wxApp/pages/webview/index.js
onMessage: function (e) {
  var dataList = e.detail.data || [];
  for (var i = 0; i < dataList.length; i++) {
    var msg = dataList[i];
    if (msg.type === 'requestOpenid') {
      // 处理请求：返回 openid
      this.postMessageToWebview('miniProgramOpenid', {
        openid: getApp().globalData.openid
      });
    }
  }
}
```

**可靠性**：⚠️ 中 — 消息**异步延迟触发**，部分微信版本在页面离开时才触发

**注意**：
- 小程序端通过 `postMessageToWebview` 回传是单向的，不保证 H5 立即收到
- 不能用于需要实时响应的场景（如支付结果）
- 适合"触发某个动作"类消息（跳转登录、退出等）

## 方法四：window.postMessage（主页面 ↔ iframe）

**原理**：SPA2.0 主页面通过 `<iframe>` 嵌入第三方页面，使用 `window.postMessage` 实现跨域通信。

**适用场景**：主页面传递用户身份给 iframe、iframe 通知主页面打开支付页

### 主页面 → iframe

```js
// webview-spa2.0/js/app.js - switchToWebview 中
var iframe = document.getElementById('webview-iframe');
iframe.onload = function () {
  iframe.contentWindow.postMessage({
    type: 'fsj:userData',
    data: {
      openid: localStorage.getItem('fsj_openid') || '',
      userId: localStorage.getItem('fsj_token') || '',
      userName: JSON.parse(localStorage.getItem('fsj_user_info') || '{}').name || '',
      shangjiaRowid: localStorage.getItem('fsj_shangjia_rowid') || ''
    }
  }, '*');
};
```

### iframe → 主页面

```js
// 第三方页面（iframe 内部）
window.parent.postMessage({
  type: 'doPayment',
  data: { body: '商品', total_fee: 1 }
}, '*');
```

### 主页面监听

```js
// webview-spa2.0 中（实际通过 bridge.js 的 doPayment 方法中转）
window.addEventListener('message', function(e) {
  if (e.data && e.data.type === 'fsj:paymentResult') {
    // 处理支付结果
  }
});
```

**可靠性**：✅ 高 — 同域 iframe 即时通信，无延迟

**注意**：
- 跨域 iframe 也能用 `postMessage`，但必须指定 `targetOrigin`
- 本项目中 iframe 与主页面同域，可用 `'*'`

## 方法五：hashchange 事件 + 轮询（兜底检测）

**原理**：结合 `hashchange` 事件监听和定时轮询，确保不遗漏任何状态变化。

**适用场景**：登录状态恢复、支付结果兜底检测

### hashchange 监听

```js
// webview-spa2.0/js/app.js - init 中
var self = this;
window.addEventListener('hashchange', function () {
  self.checkPaymentResult();
});
```

### 轮询兜底

```js
// 500ms 轮询一次，防止 hashchange 事件被吞
this._payPollTimer = setInterval(function () {
  self.checkPaymentResult();
}, 500);
```

**可靠性**：⚠️ 中 — 轮询会消耗性能，但作为兜底方案很有效

**注意**：
- 轮询间隔建议 500ms~3000ms
- 页面销毁时记得 `clearInterval`
- 适合与其他方法配合使用

## 完整支付流程实战示例

以微信支付为例，展示 5 种方法的组合使用：

```
步骤  调用方              方法                        数据
───── ────────────────── ────────────────────────── ─────────────────
1     H5 iframe          Bridge.doPayment()          {body, total_fee}
       │                  wx.miniProgram.navigateTo   /pages/pay/index

2     小程序 pay 页      微信支付 wx.requestPayment   pay_params

3     小程序 pay 页      globalData + localStorage   {success, body, amount}
       │                  wx.navigateBack(-1)

4     小程序 webview 页  onShow 检测 globalData
       │                  setData({ url: ...&_pay= })  重载 webview

5     H5 app.js          checkPaymentResult()         读取 _pay 参数
       │                  createOrderAfterPayment()    创建订单

6     H5 app.js          postMessage → iframe         {type: 'fsj:paymentResult'}
       │
       iframe             收到结果，刷新 UI
```

## 方法选型对照表

| 方法 | 方向 | 可靠性 | 延迟 | 适用场景 |
|------|------|--------|------|----------|
| URL 参数 + 重载 | 小程序 → H5 | ✅ 高 | 低（页面重载） | 支付结果、登录注入 |
| globalData / localStorage | 页面间共享 | ✅ 高 | 无 | 状态暂存、配置缓存 |
| wx.miniProgram.postMessage | H5 → 小程序 | ⚠️ 中 | 高（可能延迟） | 触发登录、退出 |
| window.postMessage | 主页面 ↔ iframe | ✅ 高 | 低（即时） | 用户身份传递、操作通知 |
| hashchange + 轮询 | H5 内部检测 | ⚠️ 中 | 中（500ms） | 兜底检测、状态恢复 |

---

## 选型建议

1. **需要实时响应** → 优先用 **URL 参数 + 重载**（方法一），最可靠
2. **跨页面状态共享** → 用 **globalData / localStorage**（方法二）
3. **H5 通知小程序动作** → 用 **postMessage**（方法三），但不依赖实时性
4. **主页面与 iframe 通信** → 用 **window.postMessage**（方法四）
5. **兜底保障** → 加 **hashchange + 轮询**（方法五），防止事件丢失

**不要依赖单一方法**，关键流程（如支付）应组合使用 2-3 种方法确保数据不丢失。
