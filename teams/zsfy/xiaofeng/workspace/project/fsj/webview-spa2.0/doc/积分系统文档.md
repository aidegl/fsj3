## 一、系统概述

### 1.1 积分定位

积分是 SPA 2.0 通用商城的**用户激励与消费抵扣系统**。用户通过消费获得积分，积分可用于后续订单的抵扣，形成消费闭环。

```
用户消费 → 获得积分 → 积分抵扣 → 再次消费 → 获得更多积分
```

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **1元 = 1积分** | 所有消费统一按 1:1 比例获得积分 |
| **仅抵扣盒子价订单** | 积分只能用于盒子价（先享后付）订单抵扣 |
| **不可提现/转赠/兑换** | 积分仅限本平台消费抵扣，不产生金融属性 |
| **全额支付也可获得积分** | 即使全额立即支付不可用积分，但仍可获得积分 |
| **项目可配置开关** | 通过 `features.points` 控制是否启用积分功能 |

### 1.3 积分适用场景

| 支付方式 | 可使用积分 | 可获得积分 |
|----------|-----------|-----------|
| 盒子价（余额支付） | ✅ | ✅ |
| 盒子价（微信支付） | ✅ | ✅ |
| 盒子价（组合支付） | ✅ | ✅ |
| 全额立即支付（微信） | ❌ | ✅ |

## 三、业务规则

### 3.1 积分获取

#### 3.1.1 消费获积分

**触发时机**：订单支付成功后

**计算规则**：
```
points_earned = floor(paid_amount)
```
即：实际支付金额（元）= 获得积分数，向下取整。

**示例**：
| 支付金额 | 获得积分 |
|---------|---------|
| ¥5.00 | 5 |
| ¥12.80 | 12 |
| ¥0.50 | 0 |

**发放流程**：
```
1. 订单支付成功
2. 计算 points_earned = floor(paid_amount)
3. 更新用户表 points += points_earned
4. 写入 points_log（change_type = "earn"）
5. 更新订单 points_status = "issued"
```

#### 3.1.2 注册获积分（可选）

由项目配置决定是否启用：
```javascript
// project.config.js
{
  businessConfig: {
    registerPoints: 10  // 注册赠送积分，0 表示不赠送
  }
}
```

**流程**：
```
1. 用户注册成功
2. 如果 registerPoints > 0
3. 更新用户表 points += registerPoints
4. 写入 points_log（source_type = "register"）
```

#### 3.1.3 活动获积分（扩展）

由运营活动触发（如签到、邀请好友等），通过 `source_type = "activity"` 标识。

### 3.2 积分使用

#### 3.2.1 抵扣规则

**适用订单类型**：仅限盒子价（先享后付）订单

**抵扣比例**：1积分 = 1元

**抵扣上限**：
```javascript
// 项目可配置
{
  businessConfig: {
    maxPointsDiscountRate: 0.5  // 积分最多抵扣订单金额的 50%
  }
}
```

**实际抵扣金额计算**：
```javascript
function calculatePointsDeduction(orderAmount, userPoints, maxDiscountRate = 0.5) {
  // 最大可抵扣金额
  const maxDeductAmount = orderAmount * maxDiscountRate;
  
  // 用户积分可抵扣金额
  const pointsDeductAmount = Math.min(userPoints, orderAmount);
  
  // 取较小值
  const actualDeduct = Math.min(pointsDeductAmount, maxDeductAmount);
  
  // 实际使用积分（1:1）
  const pointsUsed = Math.floor(actualDeduct);
  
  return {
    pointsUsed,           // 使用积分数
    deductAmount: pointsUsed,  // 抵扣金额
    remainAmount: orderAmount - pointsUsed  // 剩余需支付金额
  };
}
```

#### 3.2.2 使用流程

```
1. 用户选择使用积分
2. 校验：订单是否为盒子价
3. 校验：用户积分余额是否充足
4. 计算抵扣金额
5. 扣减用户积分 points -= pointsUsed
6. 写入 points_log（change_type = "use"）
7. 订单记录 points_used
8. 生成剩余金额的支付订单
```

#### 3.2.3 积分与余额的组合使用

盒子价订单支持「积分 + 余额」组合支付：
```
订单总价 ¥10
├── 积分抵扣 ¥3（使用3积分）
├── 余额支付 ¥5
└── 微信支付 ¥2
```

**抵扣优先级**：积分先抵扣 → 余额再抵扣 → 微信支付剩余金额

### 3.3 积分退还

#### 3.3.1 退货退还

**触发条件**：已使用积分的订单发生退货

**退还规则**：
- 使用过的积分 → 原路退回
- 已获得的积分 → 按退货比例扣回

```javascript
// 全额退货
function refundPointsForOrder(order) {
  // 1. 退回使用的积分
  if (order.points_used > 0) {
    user.points += order.points_used;
    writePointsLog({
      change_type: 'refund',
      points: order.points_used,
      source_type: 'order',
      source_id: order.order_no
    });
  }
  
  // 2. 扣回获得的积分
  if (order.points_earned > 0 && order.points_status === 'issued') {
    user.points = Math.max(0, user.points - order.points_earned);
    order.points_status = 'refunded';
    writePointsLog({
      change_type: 'use',  // 扣回记为消耗
      points: order.points_earned,
      source_type: 'order',
      source_id: order.order_no + '_refund'
    });
  }
}
```

**部分退货**：按比例退还
```
原订单 ¥30，获得 30 积分，使用 10 积分
退货 ¥10（占 1/3）
├── 退回使用积分：10 / 3 = 3 积分
└── 扣回获得积分：30 / 3 = 10 积分
```

### 3.4 积分状态流转

```
         支付成功
            ↓
    points_status: pending → issued（积分已发放）
            ↓
        发生退货
            ↓
    points_status: issued → refunded（积分已退回）
```

## 六、项目配置

### 6.1 功能开关

```javascript
// config/project.config.js
export default {
  features: {
    points: true,  // ⭐ 是否启用积分功能
  },
  businessConfig: {
    pointsRate: 1,                    // 积分比例：1元 = X积分
    registerPoints: 10,               // 注册赠送积分（0 = 不赠送）
    maxPointsDiscountRate: 0.5,       // 积分最大抵扣比例（50%）
  }
};
```

### 6.2 配置说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `features.points` | boolean | false | 全局积分功能开关 |
| `businessConfig.pointsRate` | number | 1 | 消费获积分比例 |
| `businessConfig.registerPoints` | number | 0 | 注册赠送积分数量 |
| `businessConfig.maxPointsDiscountRate` | number | 0.5 | 积分最大抵扣比例（0~1） |

### 6.3 关闭积分的影响

当 `features.points = false` 时：
- "我的"页面不展示积分入口
- 结算页不展示积分抵扣选项
- 订单不计算/发放积分
- 但 `points_log` 表结构仍保留（为后续开启做准备）

## 七、前端实现

### 7.1 积分服务封装

```javascript
// services/points.js
class PointsService {
  constructor() {
    this.balance = 0;
  }

  /**
   * 获取用户积分余额
   */
  async getBalance() {
    const res = await window.$hap.get('/points');
    this.balance = res.data.points;
    return this.balance;
  }

  /**
   * 获取积分明细
   */
  async getHistory(params = {}) {
    return await window.$hap.get('/points/log', params);
  }

  /**
   * 计算订单可用积分抵扣
   */
  async calculateDeduction(orderAmount, orderType) {
    // 非盒子价订单不可用积分
    if (orderType !== 'box_price') {
      return { available: false, reason: '仅限盒子价订单可用积分' };
    }
    
    const res = await window.$hap.post('/points/calculate', {
      order_amount: orderAmount,
      order_type: orderType
    });
    return res.data;
  }

  /**
   * 执行积分抵扣
   */
  async use(pointsUsed, orderNo) {
    return await window.$hap.post('/points/use', {
      points_used: pointsUsed,
      order_no: orderNo
    });
  }

  /**
   * 更新UI显示
   */
  updateDisplay() {
    const el = document.getElementById('points-balance');
    if (el) el.textContent = this.balance;
  }
}

// 注册到全局
window.$points = new PointsService();
```

### 7.2 订单支付中的积分处理

```javascript
// 订单结算流程中的积分处理
async function processOrderPayment(order) {
  const payment = {
    order_no: order.order_no,
    order_amount: order.total_amount,
    points_used: 0,
    balance_used: 0,
    wechat_amount: 0
  };

  // 1. 如果用户选择了积分抵扣
  if (window.usePointsToggle && window.$auth.isLoggedIn()) {
    const calc = await window.$points.calculateDeduction(
      order.total_amount,
      order.order_type
    );
    if (calc.available) {
      payment.points_used = calc.max_points_used;
      order.remainingAmount = calc.remain_amount;
    }
  }

  // 2. 余额支付
  if (window.useBalanceToggle && order.order_type === 'box_price') {
    const balance = await window.$auth.getBalance();
    payment.balance_used = Math.min(balance, order.remainingAmount);
    order.remainingAmount -= payment.balance_used;
  }

  // 3. 微信支付剩余
  payment.wechat_amount = order.remainingAmount;

  // 4. 提交支付
  return await window.$hap.post('/pay/submit', payment);
}
```

## 九、常见问题

### 9.1 积分会过期吗？

当前版本积分**不设有效期**，永久有效。后续可根据运营需求增加有效期机制。

### 9.2 积分可以转赠给其他用户吗？

**不可以**。积分仅限本人使用，不可转赠、不可提现、不可兑换余额。

### 9.3 全额支付为什么不能使用积分？

全额立即支付是标准零售模式，积分系统定位为**盒子价（先享后付）的辅助激励工具**，因此全额支付不可使用积分。但全额支付同样可以获得积分，鼓励用户多消费。

### 9.4 如何防止积分刷取？

- 积分仅在实际支付成功后发放
- 退款时按比例扣回积分
- 订单状态变更触发积分状态同步更新
- 可在项目配置中调整 `maxPointsDiscountRate` 控制风险

### 9.5 多项目之间积分通用吗？

**不通用**。每个项目的积分独立计算，用户在不同项目中拥有各自独立的积分余额。通过 `project_id` 隔离。
