## 一、概述

智能体的"大脑"工作方式：**动机驱动 + 高价值缓存 + 闭环任务流**。

- **动机来源**：任务维（sew=7目标）+ 计划维（sew=8计划）双驱动
- **知识管理**：通过 fsj API 把高复用/高权重/高置信度数据缓存到本地
- **缓存分类**：临时读取 / 过程文件 / 最终成果
- **任务闭环**：完成后删过程缓存 + 上传成果 JSON 到服务器

```
┌─────────────────────────────────────────────────┐
│        智能体思考-行动-归档循环                  │
│                                                 │
│   任务触发 → 拉缓存 → 思考 → 行动 → 反思       │
│                       ↓                         │
│                    成果产出                       │
│                       ↓                         │
│              删过程 + 传成果                      │
└─────────────────────────────────────────────────┘
```

---

## 二、动机模型

智能体的**所有行动动机**都通过两个维度驱动（**推测 sew=7/8，待用户确认**）：

### 2.1 任务维（sew = "7目标"）

**做什么** —— 上级/组织下达的目标。

来源：
- 用户显式分配（"写一篇文档"）
- 自动触发（定时任务、事件监听）
- 从目标分解（组织目标 → 个人目标）

### 2.2 计划维（sew = "8计划"）

**怎么做** —— 智能体自己的计划/待办。

来源：
- 任务维的大目标分解为小步骤
- 自己提出的计划（"我要学习 X"）
- 复盘产生的改进计划

### 2.3 双驱动关系

```
任务维 (7) ：方向性 —— 我要达成什么
计划维 (8) ：路径性 —— 我要怎么达成
          ↓
      动机 = 任务 + 计划
```

没有任务维 → 智能体无方向（不知道该做什么）
没有计划维 → 智能体无路径（不知道怎么开始）

## 三、思考循环

智能体每执行一个任务都经历**六阶段循环**（每个阶段对应 sew 维度）：

| 阶段 | sew 维度 | 作用 |
|---|---|---|
| **1. 感知** | 7目标 | 任务/计划触发，感知动机 |
| **2. 定向** | 1技能 + 9信息 | 查缓存，理解当前上下文和能力 |
| **3. 决策** | 8计划 + 2想法 | 规划行动步骤，产生方案 |
| **4. 行动** | 3项目 + 4交流 | 执行任务，协作沟通 |
| **5. 反思** | 12复盘 | 评估结果，提炼经验 |
| **6. 归档** | 11仓 | 删过程缓存，上传成果 |

循环可以嵌套 —— 一个复杂任务内会有多个小循环（子任务各自走完 6 阶段）。

## 四、缓存机制

### 4.1 高价值数据筛选

智能体通过 fsj API 从云端（明道云 shangpin 表）拉取数据时，**只缓存高价值数据**，避免本地 JSON 膨胀。

筛选标准（**阈值为推测，待确认**）：

| 维度 | 字段 | 阈值（推测）| 含义 |
|---|---|---|---|
| 高复用 | `guanjianci` | 命中 ≥ 3 次 | 被多条数据共用的标签，说明是核心概念 |
| 高权重 | `quanzhong` | ≥ 50 | 展示/检索优先级高 |
| 高置信度 | `zhixindu` | ≥ 0.7 | 数据可信度高 |

满足**任一**条件即纳入缓存。

### 4.2 缓存三分类

每个缓存节点都有 `_cacheType` 字段（**新增系统字段，待确认**）：

| _cacheType | 含义 | 生命周期 |
|---|---|---|
| `temp` | 临时读取 | 任务执行中读取的参考数据。任务结束即删 |
| `process` | 过程文件 | 思考/行动中产生的中间产物。任务结束即删 |
| `final` | 最终成果 | 任务产出，可复用、可上传。上传后删除本地 |

### 4.3 缓存生命周期

```
任务开始
   ↓
拉缓存（高价值数据 → 本地 12w.json，标记 _cacheType=temp）
   ↓
思考循环（执行任务 → 产生中间产物 → 标记 _cacheType=process）
   ↓
任务完成
   ↓
清理（删除所有 temp/process 节点）
   ↓
归档（把 final 节点通过 fsj API 上传到明道云 → 本地删除）
   ↓
回到 idle
```

### 4.4 缓存文件格式

缓存文件用 **十二维 JSON 格式**，每个节点除常规字段外带系统字段：

```json
{
  "rowid": "cache-xxx",
  "mingcheng": "某高价值概念",
  "sew": "1技能",
  "guanjianci": ["tag1", "tag2"],
  "quanzhong": 80,
  "zhixindu": 0.85,
  "_cacheType": "temp",
  "_taskId": "task-2026-07-05-001",
  "_step": 2,
  "children": []
}
```

## 五、完整任务流

一个任务从触发到归档的完整流程：

### 步骤 1：任务触发
- 任务维（sew=7）或计划维（sew=8）产生新任务
- 创建 `_taskId` 标识

### 步骤 2：拉缓存
- 调 fsj API（fsj-search）查询 sew=7/8 相关数据
- 按高价值筛选（复用/权重/置信度）
- 写入本地 `cache-{_taskId}.12w.json`，节点标记 `_cacheType=temp`

### 步骤 3：思考循环
- **定向**：读缓存，理解上下文
- **决策**：产生方案（写 `_cacheType=process` 节点）
- **行动**：执行任务（调用外部 API、写文档等）
- **反思**：评估结果（写 `_cacheType=process` 复盘节点）

循环可能多轮（子任务嵌套）。

### 步骤 4：成果产出
- 任务完成，把最终产出标记为 `_cacheType=final`
- final 节点是十二维 JSON，可直接复用

### 步骤 5：清理
- 删除所有 `_cacheType=temp` 节点（临时参考，无复用价值）
- 删除所有 `_cacheType=process` 节点（过程文件，无复用价值）
- 只保留 `final` 节点

### 步骤 6：上传
- 调 fsj API（fsj-dimensions-api addRow）把 `final` 节点的十二维 JSON 上传到明道云 shangpin 表
- 上传成功后，本地删除 `final` 节点
- 本地缓存文件清空

### 步骤 7：复盘记录
- 任务经验写入 sew=12复盘 节点
- 经验节点**不入缓存**（等下次被高价值筛选时自然进缓存）

## 六、示例：写文档任务

智能体接到任务"写一篇关于 X 的文档"，完整思考流：

```
[1. 任务触发] sew=7目标
  → "写一篇关于 X 的文档"

[2. 拉缓存] sew=1技能 + 9信息
  → 查 "X" 相关高价值概念
  → 本地缓存 5 个节点（_cacheType=temp）

[3. 定向] 读缓存，理解 X 是什么
  → 缓存里 5 个节点都是 sew=1技能 的核心概念

[4. 决策] sew=8计划 + 2想法
  → 决定文档结构：3 节，每节对应 1-2 个缓存概念
  → 写 `_cacheType=process` 节点：文档大纲

[5. 行动] sew=3项目 + 4交流
  → 写文档正文
  → 产生 `_cacheType=process` 节点：草稿

[6. 反思] sew=12复盘
  → 自我评估：文档覆盖 3/5 个概念，缺 2 个
  → 决定补充（回到步骤 4 的小循环）

[7. 成果产出] _cacheType=final
  → 完成文档的十二维 JSON（mingcheng/正文/标签/维度）

[8. 清理]
  → 删除 temp/process 节点
  → 保留 final 节点

[9. 上传]
  → fsj-dimensions-api addRow 上传最终文档
  → 本地删除 final
  → 缓存文件清空

[10. 复盘记录] sew=12复盘
  → 写经验："文档任务中，先拉高价值缓存再写，效率更高"
```

## 七、和十二维 JSON 的关系

| 角色 | 格式 | 说明 |
|---|---|---|
| 缓存文件 | 十二维 JSON | 带系统字段 `_cacheType`/`_taskId`/`_step` |
| 最终成果 | 十二维 JSON | 纯业务字段，上传前剥离系统字段 |
| 概念树 | 十二维 JSON | 智能体的"长期记忆" |

缓存文件是十二维 JSON 的**扩展用法**（加系统字段），成果 JSON 是十二维 JSON 的**标准用法**。
