# 内容元数据使用指南

> 统一内容管理 · AI 时代的数据基础设施

---

## 一、什么是内容元数据？

### 1.1 核心理念

在 AI 时代，平台上的所有内容——**商品、积分商品、文章、任务接单、资讯、活动**——本质上都是一种"内容"。传统做法是为每种内容建独立的表，导致知识库构建、搜索、推荐时需要合并多表查询，效率低下且结构混乱。

**内容元数据**方案：将所有内容类型统一到一张表中，通过 `leixing`（类型）字段区分，每条内容自带元数据（标题、描述、价格、分类、权重等）。

```
┌─────────────────────────────────────────────────┐
│              传统做法（多表分离）                    │
│                                                 │
│  商品表    积分商品表    文章表    任务接单表       │
│  ─────    ────────    ─────    ────────        │
│  各表字段不同，AI 搜索时要分别查再合并               │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│            内容元数据做法（一表统一）                  │
│                                                 │
│           统一内容表 (neirong)                    │
│  ┌──────────────────────────────────────┐      │
│  │ leixing = "商品"  → 过滤出商品内容    │      │
│  │ leixing = "文章"  → 过滤出文章内容    │      │
│  │ leixing = "任务"  → 过滤出任务内容    │      │
│  └──────────────────────────────────────┘      │
│  一条 SQL 搞定，AI 知识库直接全文检索              │
└─────────────────────────────────────────────────┘
```

### 1.2 核心优势

| 优势 | 说明 |
|------|------|
| **AI 友好** | 知识库 / RAG 系统直接查一张表，不用合并多表 |
| **搜索统一** | 全文搜索一次命中所有内容类型 |
| **灵活扩展** | 新增内容类型只需加一个 `leixing` 枚举值 |
| **商家自定义** | 组件层面自由组合，想展示什么就配置什么 |
| **权重排序** | 统一权重字段控制所有内容类型的展示优先级 |

## 二、字段结构

### 2.1 完整字段清单

| 字段名 | 类型 | 别名 | 说明 | 示例 |
|--------|------|------|------|------|
| `zdbh` | 自动编号 | 自动编号 | 系统主键，自动生成 | `0001`, `0002` |
| `mingcheng` | 文本框 | 名称 | 内容标题/名称 | "校园蒙面社交酒吧门票" |
| `shangjia1` | 检查框 | 上架 | 是否上架展示 | `true` / `false` |
| `ptxz` | 数值 | 拼团限制 | 拼团人数上限（0=不拼团） | `10` |
| `ptrq` | 日期和时间 | 拼团日期 | 拼团截止/过期时间 | `2026-08-01 23:59` |
| `ptyh` | 关联记录 | 拼团用户 | 已参与拼团的用户记录 | 关联用户表 |
| `quanzhong` | 数值 | 权重 | 展示优先级，越大越靠前 | `100` |
| `leixing` | 下拉 | 类型 | 内容类型分类 | `商品`、`文章`、`任务` |
| `chengbenjia` | 金额 | 成本价 | 商家成本价（仅商品类） | `50.00` |
| `jifen` | 数值 | 积分 | 兑换所需积分数 | `50` |
| `tejia` | 金额 | 特价 | 促销/特价（仅商品类） | `39.90` |
| `url` | 文本框 | url | **页面跳转地址**（见下方详解） | `product-detail` |
| `shoujia` | 金额 | 售价 | 正常售价 | `99.00` |
| `mdnr` | 文本框 | markdown内容 | 详细描述，支持 Markdown | 商品详情/文章内容 |
| `wznr` | 文本框 | 文字内容 | 纯文字描述（不含 Markdown） | 简短描述 |
| `zhutu` | 附件 | 主图 | 封面/主图图片 | 图片文件 |
| `shangjia2` | 关联记录 | 商家 | 所属商家记录 | 关联商家表 |
| `guanjianci` | 关联记录 | 关键词 | SEO/搜索关键词标签 | 关联标签表 |
| `spfl` | 关联记录 | 商品分类 | 所属分类 | 关联分类表 |
| `fu` | 关联记录 | 父 | 父内容/父评论的 rowid（双向关联） | 文章 rowid / 父评论 rowid |
| `zi` | 关联记录 | 子 | 子评论/子内容列表（双向关联） | 关联到同表子记录 |

### 2.2 类型枚举值（leixing）

根据业务场景，`leixing` 字段可包含以下值：

| 类型值 | 说明 | 核心使用字段 |
|--------|------|-------------|
| `商品` | 普通商品 | mingcheng, shoujia, chengbenjia, zhutu, spfl |
| `积分商品` | 积分兑换商品 | mingcheng, jifen, ptxz, ptrq, zhutu |
| `文章` | 资讯/教程/动态 | mingcheng, mdnr, wznr, zhutu, guanjianci |
| `任务` | 任务接单 | mingcheng, shoujia, mdnr, ptxz |
| `活动` | 促销活动 | mingcheng, ptrq, mdnr, zhutu |
| `评论` | 内容评论 | mingcheng, fu, zi, fabuzhe, leixing |

> **提示**：新增类型时，只需在下拉选项中添加即可，表结构无需改动。

### 2.4 评论系统设计

评论功能基于同一张内容表（`shangpin`），通过 `leixing = "评论"` 区分，使用 `fu`/`zi` 双向关联实现两级嵌套。

#### 评论数据结构

| 字段 | 说明 | 一级评论 | 回复评论 |
|------|------|---------|---------|
| `leixing` | 内容类型 | `"评论"` | `"评论"` |
| `mingcheng` | 评论内容 | 用户输入的评论文字 | 回复内容 |
| `fu` | 父记录 | 指向被评论的文章 rowid | 指向被回复的评论 rowid |
| `zi` | 子记录 | 指向该评论的所有回复 | 空（二级评论无子级） |
| `fabuzhe` | 发布者 | 关联用户表 | 关联用户表 |
| `shangjia2` | 商家 | 关联商家表 | 关联商家表 |

#### 两级嵌套逻辑

```
文章 (rowid: A)
├── 评论1 (fu=A)          ← 一级评论
│   ├── 回复A (fu=评论1)   ← 二级回复
│   └── 回复B (fu=评论1)   ← 二级回复
├── 评论2 (fu=A)          ← 一级评论
│   └── 回复C (fu=评论2)   ← 二级回复
```

超过两级的回复通过 **@用户名** 的方式在评论文字中体现，不再创建新的嵌套层级。

#### 前端展示逻辑

1. 加载一级评论：`leixing="评论" AND fu=文章rowid`
2. 加载二级回复：`leixing="评论" AND fu=一级评论rowid`
3. 默认加载 10 条，滑到底部加载更多
4. 按创建时间倒序排列（最新在前）

### 2.5 URL 与页面跳转机制

`url` 字段控制用户点击内容后跳转的目标页面，只有两种情况，通过**是否以 `http` 开头**来区分：

| url 格式 | 跳转类型 | 前端处理 | 示例 |
|----------|---------|---------|------|
| 以 `http://` 或 `https://` 开头 | **外部链接** | 打开 webview 或外部 H5 | `https://example.com/landing` |
| 其他值 | **通用页面别名** | 跳转到前端已写好的 HTML 模板页 | `product-detail` |

> **判断逻辑**：有 `http` 就是外部链接，没有就是通用页面别名。不需要额外字段。

#### 前端判断逻辑

```javascript
// 点击内容卡片时的跳转处理
function handleContentClick(content) {
  var url = content.url;
  
  // 1. 空值：根据 leixing 自动选择通用页面
  if (!url || url.trim() === '') {
    var defaultMap = {
      '商品': 'product-detail',
      '文章': 'article-detail',
      '任务': 'task-detail'
    };
    url = defaultMap[content.leixing] || 'default-detail';
  }
  
  // 2. 判断：有 http 就是外部链接，否则是通用页面别名
  if (url.indexOf('http') === 0) {
    // 外部链接，打开 webview
    window.App && window.App.switchToWebview(url);
  } else {
    // 通用页面别名，跳转到前端模板页
    window.App && window.App.switchToPage(url, { rowid: content.zdbh });
  }
}
```

#### 通用页面模板清单

前端预置的通用页面（别名即跳转名）：

| 别名 | 对应的通用模板 | 使用的元数据字段 |
|------|--------------|----------------|
| `product-detail` | 通用商品详情页 | mingcheng, shoujia, chengbenjia, tejia, zhutu, mdnr |
| `article-detail` | 通用文章详情页 | mingcheng, zhutu, mdnr, wznr, guanjianci |
| `task-detail` | 通用任务详情页 | mingcheng, shoujia, mdnr, ptxz, ptrq |
| `default-detail` | 通用内容详情页（兜底） | mingcheng, zhutu, mdnr, wznr |

> **扩展**：新增通用模板时，只需在前端注册 HTML 模板组件，商家无需改动，直接在 `url` 填模板名即可使用。

## 三、商家自定义展示

### 3.1 组件级内容配置

商家可以在任意组件中自定义要展示的内容，通过筛选条件组合：

```javascript
// 示例：首页组件配置
{
  "componentType": "content-list",
  "config": {
    // 要展示的内容类型
    "leixing": "商品",
    // 过滤条件
    "filters": [
      { "controlId": "shangjia1", "value": true },    // 已上架
      { "controlId": "spfl", "value": "饮品" }        // 饮品分类
    ],
    // 排序规则
    "sortBy": "quanzhong",  // 按权重排序
    "sortOrder": "desc",
    // 显示字段
    "displayFields": ["mingcheng", "shoujia", "zhutu", "tejia"]
  }
}
```

### 3.2 典型展示场景

| 场景 | 配置示例 |
|------|---------|
| **首页商品列表** | `leixing=商品, shangjia1=true, sortBy=quanzhong` |
| **积分商城** | `leixing=积分商品, jifen>0, ptxz=0` |
| **拼团专区** | `leixing=积分商品, ptxz>0, ptrq>now` |
| **资讯文章流** | `leixing=文章, shangjia1=true, sortBy=zdbh` |
| **全局搜索** | 不限制 leixing，全文搜索所有类型 |
| **任务大厅** | `leixing=任务, shangjia1=true` |

### 3.3 前端调用示例

```javascript
// 通过 fsj-api.js 统一接口查询
FsjApi.getContentList({
  leixing: '商品',           // 内容类型
  shangjia1: true,          // 仅上架内容
  spfl: '饮品分类rowid',     // 分类过滤
  page: 1,
  pageSize: 20
}).then(function(res) {
  // 统一返回格式，所有类型数据走同一套渲染逻辑
  renderCards(res.data.rows);
});
```

## 四、AI 知识库集成

### 4.1 RAG 检索增强

内容元数据表天然适合 RAG（检索增强生成）系统：

```
用户提问 → AI 搜索 → 统一内容表
                    ↓
         一条查询命中商品/文章/任务
                    ↓
         返回最相关的内容给 AI 作答
```

### 4.2 搜索策略

```sql
-- 关键词搜索所有内容类型
SELECT * FROM neirong
WHERE (
  mingcheng LIKE '%关键词%'
  OR mdnr LIKE '%关键词%'
  OR wznr LIKE '%关键词%'
  OR guanjianci LIKE '%关键词%'
)
AND shangjia1 = 1
ORDER BY quanzhong DESC
LIMIT 10;

-- 按类型过滤
SELECT * FROM neirong
WHERE leixing = '文章'
AND mingcheng LIKE '%AI%'
ORDER BY zdbh DESC;
```

### 4.3 向量化建议

对以下字段进行向量化嵌入（Embedding）：
- `mingcheng`（标题）— 高权重
- `mdnr` / `wznr`（描述/正文）— 核心内容
- `guanjianci`（关键词）— 语义匹配

## 五、最佳实践

### 5.1 权重管理

`quanzhong` 字段控制所有内容类型的展示优先级：

| 权重范围 | 用途 |
|---------|------|
| `100+` | 置顶推荐内容 |
| `50-99` | 重要内容 |
| `10-49` | 普通内容 |
| `0-9` | 次要内容 |

### 5.2 拼团逻辑

```
ptxz = 0  → 不拼团，直接购买/兑换
ptxz > 0  → 需要拼团，等待 ptrq 截止或人数满
ptyh      → 记录已参与的用户（关联记录）
```

### 5.3 价格字段关系

| 字段 | 商品类 | 积分商品类 | 文章/任务类 |
|------|-------|-----------|------------|
| `shoujia`（售价） | ✅ 必填 | ❌ 不用 | ❌ 不用 |
| `chengbenjia`（成本） | ✅ 商家参考 | ❌ 不用 | ❌ 不用 |
| `tejia`（特价） | ✅ 促销时用 | ❌ 不用 |  不用 |
| `jifen`（积分） | ❌ 不用 | ✅ 必填 | ❌ 不用 |

### 5.4 附件处理

`zhutu` 字段存储图片附件，前端调用时：

```javascript
// 解析附件字段（明道云返回格式）
function parseImage(fileField) {
  if (!fileField) return '';
  try {
    var files = typeof fileField === 'string' ? JSON.parse(fileField) : fileField;
    return files[0].large_thumbnail_full_path || '';
  } catch(e) {
    return '';
  }
}
```

## 六、注意事项

1. **类型值统一**：新增内容时，`leixing` 的值必须与下拉选项一致（区分大小写）
2. **上架控制**：所有 `shangjia1 = false` 的内容不会在前端展示
3. **拼团截止**：`ptrq` 过期后即使 `ptyh < ptxz` 也应标记为不可参与
4. **关联记录**：`ptyh`、`shangjia2`、`guanjianci`、`spfl` 为关联字段，查询时需要 `includeControls` 指定
5. **扩展字段**：如某类内容需要额外字段，可考虑使用 JSON 扩展字段或新增专属列
