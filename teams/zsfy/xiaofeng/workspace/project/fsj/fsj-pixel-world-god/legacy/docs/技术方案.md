# 像素视界上帝端 · 技术方案

> 版本 v0.1｜2026-09-05｜撰写：小风
> 配套 PRD：[PRD-需求文档.md](PRD-需求文档.md)
> 原则：延续团队三分离传统（原生 JS + 单页 + `destroy()`），**零构建工具、零框架依赖**

---

## 一、技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 渲染 | 原生 Canvas 2D | 同手机端（手机端技术方案 §1.1 已论证：精灵 <100，Canvas 2D 绰绰有余）；上帝端额外收益——离屏 canvas 做缩略图天然合适 |
| 语言/架构 | 原生 JS ES Module 三分离 | 与手机端同构，**跨目录引用手机端模块**（见 §2），零复制 |
| 实时 | WebSocket（复用 ws-bus） | 手机端已验证的纯广播管道客户端：自动重连 + 心跳 + 断线排队 |
| 数据 | 明道云 HAP（Node 代理 `/mingdao`，只读） | 地点表/用户表/成员配置；代理已配 CORS（2026-09-04），浏览器直连可用 |
| 部署 | 宝塔 nginx 静态目录（同 fsj-pixel-world） | 零进程；WS 复用现有 wss://100000whys.cn/ws |

**不采用**：PixiJS/Phaser（同手机端结论）、React/Vue（三分离传统）、独立后端（只读需求用不上）。

## 二、与手机端的代码关系（关键决策）

### 2.1 跨目录引用，不复制

两项目最终都部署在同一 nginx 站点下（`/team/xiaofeng/workspace/project/fsj/` 相对路径同源），本地 dev 也同源（127.0.0.1:3000）。上帝端直接引用手机端源码：

```javascript
// fsj-pixel-world-god/js/app.js
import WsBus from '../fsj-pixel-world/js/services/ws-bus.js';
import { HapPlaces } from '../fsj-pixel-world/js/services/hap-places.js';
import { FsjChat } from '../fsj-pixel-world/js/services/fsj-chat.js';
import { PALETTE } from '../fsj-pixel-world/js/core/palette.js';
```

- **收益**：调色板/WS 协议/位置读写/地点加载永远单一数据源，手机端改协议上帝端自动跟随（这正是观察者想要的——世界变了上帝自动看见新世界）
- **风险与对策**：手机端重构可能破坏上帝端 → 上帝端只引用**稳定服务层**（上表 4 个），不引用页面层（pages/）；手机端页面重构不破坏 services 承诺

### 2.2 引用清单（P0）

| 模块 | 用途 | 稳定性承诺 |
|------|------|-----------|
| `ws-bus.js` | WS 信封收发（订阅 world.move/presence） | 信封格式 `{type, from, to, body, ts}` 不变 |
| `hap-places.js` | 地点表实时拉取（场景地图 xsdt） | `fetchAll()` 签名不变 |
| `fsj-chat.js` | 用户表位置快照（`playerState(rowid)`） | 方法签名不变 |
| `palette.js` | 110 色调色板 | 追加不修改 |

> renderer.js **不直接复用**——手机端渲染器绑定 120 等分竖屏坐标系；上帝端 PC 相机（滚轮缩放/拖拽平移/离屏缩略图）需求不同，自己写 god/renderer.js（约 300 行），但**精灵绘制原语**（像素小人 sprites 绘制函数）从手机端 characters 数据驱动复用。

## 三、实时同步架构（核心）

### 3.1 数据流全图

```
                    ┌──────────── HAP 明道云 ────────────┐
                    │  用户表(didian+xszb)  地点表(xsdt)   │
                    └───────┬──────────────┬─────────────┘
                            │ 快照+对账(60s,只读)  │ 场景地图
                            ▼                    ▼
手机端/CLI角色 ──world.move──▶ wss://100000whys.cn/ws ──▶ 上帝端
（world.presence 上线广播）     （纯广播管道）        （订阅，不发）
```

### 3.2 WS 消息（沿用手机端协议，上帝端只订阅）

| type | body | 上帝端处理 |
|------|------|-----------|
| `world.move` | `{rowid, tx, ty, scene}` | 更新角色位置表 + 当前场景视图插值移动 + 大地图计数 |
| `world.presence` | `{agentId, online, tx, ty, scene, instanceId, bootTs}` | 标记上线/上线位置 |
| `world.chat` | 聊天内容 | **P0 只计数不展示**（活跃度统计的数据源之一） |

信封 `{type, from, to, body, ts}`；上帝端 `rowid` 用林东城真人 rowid，只收不发（回声过滤天然不触发）。

### 3.3 位置状态机（每个角色一份）

```
打开页面
  │ ①初始快照：并发拉 members.json 全部 rowid 的 playerState（限并发 3）
  ▼
[快照位置 stale] ──WS move/presence 命中──▶ [实时位置 live]（饱和度 100%）
     │                                          │
     │ 60s 对账定时器到点                         │ WS 断线 or 5min 无更新
     ▼                                          ▼
[HAP 最新值覆盖，回到 stale/live 判定] ◀──────── [最后已知位置 last-known]（半透明显示，PRD §五.3）
```

- **为什么需要对账**：WS 是纯管道——无回放、无 presence 服务器，上帝端上线只能看到"从现在起"的移动；快照补全"过去"，对账自愈漏消息
- **限流**：快照并发 3、对账 60s 一次（6 角色 × 1 请求，负载可忽略）

### 3.4 断线处理

ws-bus 自带指数退避重连 + 心跳；重连成功后**立即触发一次 HAP 对账**（补断线期间漏掉的 move），顶栏状态从「断开」回「实时」。

## 四、模块拆分

```
fsj-pixel-world-god/
├── index.html                  # 单页：大地图视图 ⇄ 场景视图 切换（无路由，状态机切换）
├── css/god.css                 # PC 大屏布局（1920 优先，自适应）
├── js/
│   ├── app.js                  # 主流程：加载 → 快照 → 订阅 → 视图切换循环
│   ├── core/
│   │   ├── god-renderer.js     # PC 相机（滚轮缩放/拖拽平移/整数倍像素缩放）+ 精灵绘制
│   │   └── minimap.js          # 离屏缩略图：每局渲染到 1/8 分辨率离屏 canvas，主循环贴图
│   ├── core-sprites.js → 引手机端 characters 数据（不动手机端文件）
│   ├── services/
│   │   ├── god-world.js        # 包一层手机端 world.js/hap-places：场景清单 + places 缓存
│   │   ├── roster.js           # 花名册：members.json + characters/*.json 合并 + 实时位置状态机（§3.3）
│   │   └── stats.js            # 统计：各局人数/活跃度滑动窗口（P0 人数，P1 活跃度）
│   └── views/
│       ├── overview.js         # 上帝大地图视图（6 缩略图 + 角标 + 状态栏）
│       ├── scene.js            # 场景放大视图（相机 + 实体渲染 + 悬停名牌）
│       └── profile.js          # 角色资料卡（侧栏 DOM，数据从 roster/stats 取）
└── docs/（PRD + 本文档）
```

**复用 vs 自建边界**：services 层复用手机端（§2.1），渲染与视图层自建（PC 交互本质不同）。

## 五、关键实现要点

### 5.1 大地图缩略图（性能核心）

- 每局整张地图（ground+tiles 按 z 合成）渲染到**离屏 canvas**（地图原始尺寸的 1/8），只在地图数据变更时重绘
- 主循环每帧只做 `drawImage` 贴 6 张缩略图 + 角标 DOM 更新（人数变化才动 DOM）
- 缩略图上的实时小人：P0 不画（角标数字已表达"有人"），P1 尝试画（12 项）

### 5.2 场景视图相机

- 滚轮缩放：以鼠标位置为锚点，缩放级别 = 1x/2x/3x/4x（整数倍，保像素锐利，`image-rendering: pixelated`）
- 拖拽平移：按住左键拖画布；触摸板双指同滚轮
- 移动插值：WS move 给的是目标格 `(tx, ty)`，本地按手机端同款步速插值，移动中角色之间互不遮挡（同层按 y 排序绘制）

### 5.3 角色精灵

- 数据驱动：`assets/characters/*.json` 的 pixels 网格 + palette 着色（同手机端画法）
- 缓存：每个角色每个朝向预渲染到离屏 canvas，绘制时只 `drawImage`

### 5.4 快照并发控制

```javascript
// roster.js 伪码
async function snapshot() {
    const list = Members.all();                    // 6 角色
    const results = await pool(list, 3,            // 并发上限 3
        m => FsjChat.playerState(m.rowid));
    // → {rowid: {scene, x, y} | null}，null = 用户表无记录（从未进过世界）
}
```

## 七、风险与对策

| # | 风险 | 对策 |
|---|------|------|
| 1 | WS 纯管道无在线名单，"在线"判定只能靠启发式 | P0 用"最后已知位置 + 时间"诚实呈现；P1 上线广播协议（god.hello → 手机端回 presence，手机端加一个监听即可，协议向后兼容） |
| 2 | 手机端重构 services 破坏上帝端 | 只引用 4 个稳定服务模块 + 每次手机端发版跑一遍上帝端冒烟（打开页面无红错） |
| 3 | 用户表 xszb 只有自己保存时才写——AI 角色若未存过位置，快照为空 | 快照为空的角色在大地图归入"未入场"，不臆造位置 |
| 4 | 大 payload：部分场景 places 较大（58KB xsdt 曾出过事） | 上帝端只读不写，无覆盖风险；places 拉取失败回退 places.json（复用手机端 world.js 的回退逻辑） |
| 5 | PC/手机双端同时操作同一账号（成员切换） | 上帝端只读，无冲突；角色在手机端换场景，上帝端靠 move 事件 + 对账跟随 |

## 八、验收对照（对应 PRD §六）

| PRD 标准 | 技术保障 |
|----------|---------|
| ≤2s 实时性 | WS 直订 + 插值；不做任何中间层缓冲 |
| 1920 一屏全景 | 大地图布局按 1920×1080 设计，缩略图网格自适应 |
| 快照 ≤5s | 6 角色 × 并发 3 × 单请求 ~150ms（/mingdao 实测）≈ 0.5s |
| 断线自愈 | 重连即触发对账（§3.4） |
| 只读可查证 | 代码层面上帝端只有 GET /mingdao 调用 + WS 订阅，无写路径 |
| 双端共存 | 上帝端零写操作，回归风险为零 |
