# 像素视界上帝端（fsj-pixel-world-god）功能文档

> 本文记录系统当前**实际实现**的全部功能，与代码同步维护。
> 定位：PRD v2 的素材底稿 + 新会话的功能索引。
> 最后更新：2026-10-19（与 flow-20261019-test-001 同步）

## 一、架构总览

```
agent 干活 → flow-*.json（唯一真相）
              ↓ flow-write.mjs 统一写入口（流json + loopstate 行动行）
server.mjs :8321
  ├─ 静态托管 index.html + 资产
  ├─ /api/data（flow + plan + hits 聚合，每请求现读）
  ├─ /api/events（SSE 备用）
  ├─ /ws（WebSocket 主通道，fs.watch 变更即推）
  └─ 静态资源：routes.json / emoji-map.json / mermaid.min.js
              ↓
index.html 上帝端页面（纯前端渲染）
```

**启动**：`node server.mjs`（默认 8321）。**不要用 VSCode Live Preview**（不提供 /ws 和 /api/data）。

## 二、任务与计划流面板（底部左）

| 功能 | 行为 |
|---|---|
| 任务列表 | plan-日期.json 的 steps，二级 tab（全部/组织/已完成） |
| 进度徽标 | 每任务右侧 `n/N`——n=已完成主步数，N=主步总数（跨流统计，子步不计）；无流回退 P 号 |
| 点击任务 | 展开详情（标题/标签/详情/验收），并切入其流 |
| 计划流标题栏 | 「计划流」+ **时间开关**（操作时间显隐）+ **跟随开关**（指针跟随），两开关右对齐带文字标签 |
| 队列模型 | 流列表显示顺序 = 已完成（按序）→ 进行中 → 待办问题队列（按报告序）→ blocked 后置；**continuous 观察型不占显示位** |
| 标题栏常显 | 无流时标题栏仍在，详情区显示"尚未建流" |

## 三、Step 与子步

| 规则 | 内容 |
|---|---|
| 主 step | `no` 整数；字段 no/title/type/module/status/startedAt/endedAt/emo/mood/decision/output/note/demoHits/blockedOn/flows |
| 子步 | `no` 小数字符串（`20.1`）+ `depth:1`，紧跟父步；显示缩进 20px + `no.` 前缀 |
| 子步用途 | 任务细化、执行障碍、done 后的收尾操作——**与父步渲染逻辑完全一致**（情绪/流程图/指针一视同仁），仅差缩进层级 |
| 老板的问题 | 一律开**主 step**（`问题：`前缀），不是子步——顶层一眼可见 |
| 情绪时序铁律 | 插入时不带 emo；执行中不带 emo；**只有执行结束才写 emo+mood** |
| 心理活动 | `mood` ≤10 字，挂在情绪后（`🥳 成就 · 时序终于对了`），**不许每回雷同** |
| SEL 身份制 | 选中状态存 step 的 **no（编号）**不存数组下标——数组位移免疫，指针绝不跟丢 |

## 四、流视图三形态（底部右）

状态机：**执行中检索阶段 → 检索结果表格（自动）→ 到情绪 → 角色动画（自动）→ 完成 → 定格视图**

| 形态 | 触发 | 内容 |
|---|---|---|
| 流程图 | 无emo无检索数据的执行态；done 步的定格（思考型） | mermaid 决策图（Q→module→选/弃→状态），实时刷新 |
| 检索结果表格 | 执行中且有 demoHits（检索阶段）；done 的检索型定格 | 七列：时间/方式/查询/命中/Top1/关联/漏召；**方式列含方法·端点·耗时**，自动换行；检索蓝竖线+外框 |
| 角色动画 | 执行中且写入 emo（到达情绪阶段）；点情绪行手动触发 | 小风 GIF 全屏黑底，done 后自动切回 |
| 情绪行点击 | 流列表情绪行 → 动画叠加视图；点名称行 → 退出回流程图 | 同 step 内切换无盲区 |

## 五、指针与跟随

| 规则 | 行为 |
|---|---|
| 白三角 | 指向 `now.step_no`（按 no 对号，写竞态免疫）；执行中**居中聚焦**并自动滚动 |
| 完成语义 | step 完成后指针**停在最近完成步**，不切下一个 |
| 跟随开关 | 标题栏 iOS 式开关，关=自由浏览 |
| 写入顺序 | flow-write 先写流文件、**loopstate 最后写**——最终推送永远状态一致 |

## 六、检索系统

| 功能 | 行为 |
|---|---|
| hap-search.mjs | HAP getFilterRows 真实检索，**demoHits 追加式**（多次检索全留痕，条目间蓝色分隔线） |
| 完整七段 schema | t/q/hits/top(单条标题)/miss/channel(方法·端点·耗时) |
| 0 命中 | 如实显示（漏召是金子），不装没发生 |
| 检索蓝 | #6c9be8——检索表格线框/表头/流列表命中标签统一色 |

## 七、检修系统

顶栏「🔧 检修」按钮 → 弹窗逐项排查，**只查出过事故的 7 项关键项**：

1. server 存活 /api/data（含耗时）
2. flow json 合法（ASCII 引号事故防线）
3. plan 键名 steps（任务列表空事故防线）
4. loopstate 行动行供电（断粮事故防线，**接受 0 指针=持续观察型合法态**）
5. WS 连接
6. 指针聚焦（SEL 身份制，应为 0 或 1 个白三角）
7. emoji 单源加载（📝事故防线）

每项显示 ✓/✗ + 详情 + 耗时；底部汇总；「↻ 重新检修」可复跑。
