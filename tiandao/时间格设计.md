# 时间格（Time Cell）

> [!wuming] 无名·10-22 东城命题「天道要设计一个时间格的概念」。v0.1 起草，五个设计决定全标 🟣 待你拍板——你改哪条我改哪条。

## 一、定义

**时间格 = 天道调度的最小时间单元**。天道不按「任务队列」单维运转，而是把一天切成格子：每格有归属、有使命、有产出、有对账。格是天道安排谁在什么时候干什么的**容器**，也是记忆/积分/对账的**记账单位**。

## 二、格子结构（每格六字段）

| 字段 | 含义 | 例 |
|---|---|---|
| 格id | 日期+序号 | `20261022-G3` |
| 起止 | 物理时间窗 | 10:00–12:00 |
| 维度归属 | 12维之一 | 1技能 / 8计划 |
| 使命 | 这格要干什么（一句） | 「巡检+吃地图任务1」 |
| 占用者 | 哪个 agent | 无名 / 天道自身 |
| 产出指针 | 结束时填：flow step / 文档 / 🔵标记 | s8.13x |

## 三、切法（🟣拍板点1：格长）

| 方案 | 格长 | 适合 |
|---|---|---|
| A **时辰格**（推荐） | 2小时/格=12格/天（子丑寅卯…） | 与天干地支体系同构；东城节律（4-5点起）天然对齐卯格开工 |
| B 番茄格 | 25分钟 | 纯执行日，太碎不宜天道层 |
| C 自适应格 | 深度工作不切、杂务切30分 | 灵活但对账模糊 |

**推荐 A+B 混合**：天道层用时辰格（12格对账），agent 内部自用番茄格——两层不打架。

## 四、天道用时间格干什么（四个用途）

1. **排班**：每格开始时天道分配使命（谁/干什么/产出要求），格内 agent 自主
2. **对账**：每格结束天道收割——产出指针有没有落盘？空格连×3 → 升级上报（这就是「禁空转」的天道层执行机制）
3. **记忆归属**：记忆/流水挂格id（对应孚骨架「时间类挂当日小时节点」——时间格就是那个小时节点的落地形态）
4. **积分与作息**：agent 按格计勤（满格=出勤）；东城作息编码进格表（卯格晨会/子格夜班），天道按格自动提醒开关机

## 五、与既有体系的关系

- **12维**：格挂维度 → 每格产出天然分类入库
- **计划流 flow**：flow 的 step 是「事」的轴，时间格是「时」的轴——交点就是「几点干了什么事」，复盘/命中数据聚合直接按格切
- **五事**：一天 12 格分配给五事（多少格干命/多少格学习），格表即五事排程的可视化
- **天道既有 Y/Z 档**：时辰格是 Z 档脚本的调度容器，小模型 judge 按「本格使命 vs 实际产出」判断

## 六、落地最小版（🟣拍板点2：要不要现在做）

1. 天道 CLI 每天零点生成当日 12 格空表（`tiandao/格表/20261022.json`）
2. 每格结束写一行收割记录（谁/产出/是否空格）
3. 空格连 3 → 上报
——半天工作量，先跑起来再进化。
