# 计划流的技术原理

计划流的技术原理
技术原理：从 json 到像素的全链路
四层：json 真相层 → fs.watch 采集层 → WebSocket/SSE 推送层 → 上帝端渲染层。每层可独立替换，接口不变。
① json 真相层
flow-YYYYMMDD-<agent>-<序号>.json 是唯一真相：任务封面（task/status/strategyNote/goalRef）+ steps[]（每步 no/type/module/title/status/decision/output/note）。改文件 = 改状态，git 天然留痕。
② 采集层：fs.watch
server 对 flows 目录挂 fs.watch——agent 每次写盘 150ms 去抖后触发。曾踩坑：并行会话把 node:fs 具名导入改掉导致 fs 未定义、watcher 静默失联——已加挂载日志自证。
③ 推送层：WebSocket + SSE 双通道
WebSocket（ws 包，/ws 路径，断线自动重连）为主；SSE（/api/events）为备。服务端毫秒级 broadcast，页面 onmessage 即渲染。Cache-Control: no-store 全响应禁缓存——浏览器缓存旧 JS 曾是「改了没生效」的元凶。
④ 渲染层：上帝端页面
左侧任务卡（P 号 = index+1 纯计算，永不手填）+ 底部流面板（状态 icon 唯一、聚焦指针唯一白色、未选中淡化）+ 右侧行动记录（命中率日志 feed）。确定性百分比六档上色——老板一眼看到哪些拼实了、哪些还困惑着。
稳定性防线：三 hook 生命周期注入
image.png

UserPromptSubmit：每轮老板消息进来 → 注入当前流状态便签（几百 token）——agent 每轮开场自动知道在哪、该干嘛
PostToolUse：每次工具调用后 → 心跳文件打点——agent loop 活跃的机制化证明
Stop：收尾时对账流 mtime，超 15 分钟未更新 → block 打回强制写流——「忘记填流」机制性杜绝
PreToolUse：「正在执行」实时采集
每次工具调用前捕获 tool_name + tool_input，翻译成动作描述（正在编辑 xxx / 正在执行命令…）写进 loopstate——页面把「⌨ 正在 coding…」升级为真实执行描述。agent loop 在干嘛，UI 一字不差。
情绪 → 做梦 → 情绪路由
每步 note 写大白话情绪（情绪脸由页面按规则算）→ 0 点入睡收缓存 → 做梦重放归堆 → 整理进时间记事 → 形成情绪路由（潜意识层）。
计划流两大特色：情绪路由 + 八格 if-row（2026-10-18 拍板）
① 情绪（必须输出）
每步 emo 字段必须输出——agent 自设：顺畅 / 困惑 / 兴奋 / 平静…
情绪路由 = 遇到什么情绪加载什么数据：困惑 → 自动展开 blockedOn 详情；兴奋 → 脉冲加速；平静 → 常规
情绪脸由页面按规则渲染（九张脸），agent 只写大白话——不是演的
白天采集 → 0 点做梦重放归堆 → 整理进时间记事 → 形成情绪路由（潜意识层）
② 八格 if-row（bage 判断行）
每个 step 可声明 bage:{main,aux}（一主一辅，最多两个）
页面渲染：主行右侧显示带边框的 chip（主=实边·辅=虚边），形如：玄武·主 值符·辅
module 字段（Ti/Te/Ni/Ne…荣格模块）继续显示为虚线框 chip——bage 与 module 并列
解决不了 → 换配对另起 step（不在原步死磕）——结果按配对沉淀八格路由经验
③ 右侧功能视图（详情面板）
点击流内任意一行 → 右侧功能视图显示该 step 的详情
如果该 step 有 bage → 显示 mermaid 可视化（八格配对关系图）
如果该 step 有 demoHits → 显示检索结果表格（列：时间/检索方式/查询/命中/Top1/关联性/漏召——与命中率日志七列一致）
两者都有 → mermaid 图在上、表格在下
都没 → 显示 decision（chosen/why/alternatives）+ output + note 的常规详情
设计闭环
step 结果 × 八格配对 × 情绪 → 沉淀到命中率日志 → 12 维复盘聚合「什么性格策略适合做什么事、什么情绪对应什么数据需求」→ 八格路由表持续进化。

子步与拆流（v1.2 · 2026-10-19 拍板）
子步：step 可在平铺数组内延展轻量子步——no 用小数字符串（"2.1"）+ depth:1 标层级；字段仅 no/title/type/status/startedAt/endedAt/note。decision、检索、八格(bage)、emo、demoHits 一律挂父步——子步是父步的内部清单。15 步标尺只数 depth=0；只允许一层 depth，再深就该拆流。
拆流：step 新增可选 flows:["flow-…"] 引用（与计划层 P→flow 完全同构）——步骤升级成独立活/派给别的 agent 时另起一条流，原步骤行渲染「⧉ 已拆流」chip 可跳转。
渲染：子步在流面板缩进 34px（frow.sub2），点击只出轻量详情（状态/时间/note）；「计划流」标题栏（标题+跟随开关）常显，没流只空详情区——与右侧「流视图」标题逻辑对称。
